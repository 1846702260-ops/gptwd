# 知遥 AGI · 公开文档中心

> 本仓库是知遥 AGI 的**公开脱敏**任务书、报告与管理索引中心。
> 本目录（`docs/`）由 K 侧一次性初始化结构，由 C 侧独立核验并记录。
> 完整内部原件仍保留在 K/C/Z/R/E 五侧共享资料库；本仓库不替代该资料库，也不构成工作自动分发或部署机制。
> 本结构与《AI 工作流统一规则》V1.4（2026-11-25）对齐，适用 ChatGPT 总协调与 WorkBuddy K/C/Z/R/E 五侧。

> R/E 四个新增目录（`10-tasks/R/`、`10-tasks/E/`、`20-reports/R/`、`20-reports/E/`）按 V1.4 §10.3 仅在对应侧首份合规文件归档时建立，不预建空壳、不重排历史。

## 角色分工

| 侧别 | 职责 |
| --- | --- |
| **K** | 核心研发。承担六核研发任务书的执行，产出开发、技术研究、测试报告（脱敏）；优先复用 R 侧已核实成果。 |
| **C** | 独立验收与集成。执行验收任务，可在既定范围内直接完整修复、补测及复验，并维护《知遥记录》。 |
| **Z** | 生产运维与真实环境验证。承担运维与环境验证任务，产出相关报告。 |
| **R** | 技术研究与隔离实验。前沿技术与外部生态研究、源码协议分析、对照实验与可复现 PoC，结论交 ChatGPT 裁决。 |
| **E** | 生态与扩展研发。经批准备的能力适配、技能与工具接入、非核心与界面扩展；初期机动待命。 |
| **ChatGPT（总协调）** | 统一下发任务、维护总纲与计划、汇总研究与发布信息、管理归档。 |

**分工边界**：不可逆、生产高风险、权限或范围外的操作，必须单独审批，不得由文档中心自动触发。R 的研究产物不等于正式功能交付；E 不得改动六核核心契约或生产环境。

## 任务流转

任务书由 ChatGPT 统一下发到 `10-tasks/<侧别>/`，对应侧别执行后将脱敏报告提交到 `20-reports/<侧别>/`。状态用文件命名或正文标注区分：

`已制定 → 已下发 → 执行中 → 待 C 验收（K/E 交付） → R 结论交 ChatGPT 裁决 → 待 Z 复验（如适用） → 已闭环`

不适用的阶段不强加。任务编号在整个生命周期内保持一致，不重复派单。K/E 可并行隔离开发但不得同写同一核心路径，C 为正式候选的统一集成入口。

## 命名规范

- 统一使用 **UTF-8 Markdown**。
- 任务文件建议命名：`YYYY-MM-DD_任务编号_主题.md`。
- 报告文件建议命名：`YYYY-MM-DD_任务编号_主题_报告.md`。
- 保留既有任务编号，不重复派单。
- **任务书**须包含：目标、范围、执行方、限制、验收标准、交付物。
- **报告**须区分「已验证事实」与「推测」，并写明：日期、版本/候选、结果、风险、下一步。

## 与共享资料库的关系

本 GitHub 文档中心是**公开脱敏视图**：
- 完整任务书原件、内部成长记录、审计报告原件仍存放在 K/C/Z/R/E 五侧共享资料库。
- `30-journal/` 仅放《知遥记录》的脱敏摘要，完整原件不上传公开仓库。
- 本目录**不替代**共享资料库，也**不构成**工作自动分发或部署机制。
- 「文件上传 ≠ 自动派工 / 执行」：把文件放进本仓库不会触发任何侧别自动开始工作，派工与执行仍按既有人工协调流程进行。

## 公开仓库安全边界（红线）

本仓库为**公开仓库**，任何人都可读取。严格遵守：

**禁止提交**：
- 账号、令牌、密钥、密码、凭据
- 私有链接、生产地址与内部架构细节
- 生产配置、完整内部审计原件
- 可利用的漏洞详情、敏感日志
- 用户私人聊天记录或长期记忆
- 任何未脱敏的内部资料

**特别注意**：不得因为某文件已存在于仓库根目录，就误认为它已通过保密审查。历史文件与本次文档中心初始化无关；如需处理须单独评估。

提交前应确认差异仅涉及预定目录，且不含任何疑似敏感信息。
