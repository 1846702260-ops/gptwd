## 0. 结论

S2 的三件事已经接进真实主链，不是旁路演示：

1. **一个请求一本账**：窗口 → 输出预留 → 安全余量 → 固定区 → flex，记忆/摘要/历史从同一个池子分；发送前按同一口径复核整包，超限且不可裁时**不发**。
2. **压缩先归档**：`MAX_TURNS=30` 的硬截断改为"水位判定 → 归档段 + manifest → 摘要（可失败）→ 移出热窗口"；任何一步失败都不移原文。
3. **有界恢复**：按来源 ID / 时间 / 关键词 / 会话取片段（≤limit），读取前做 scope 过滤，读取后进同一个 S1 组装器；纠错后旧值不复活。

## 2. 实施

### M1 唯一预算与真实口径

- 新增 `contextLedger.js`：`planContextBudget()` 为唯一决策者，`verifyPayload()` 做整包复核，`boundedCandidateK()` 让候选池按预算/库规模在 **6–40** 有界伸缩（默认 320 → 13），不再固定 12。
- 记忆子预算进入 `assembleContext`；历史子预算进入 `brain` 的历史装载；工具 schema 计入固定区并参与复核。
- 上限来源：`model-meta` 权威表；查不到用 `UNKNOWN_WINDOW=32000` 并标 `windowSource='unknown-conservative'`，不硬编模型上限。
- 口径：`estimator.mode='structural'`（中文×1.25 + 其它÷3.6），**不叫精确 Token**；真实 `usage` 到来后由 `tokenCalibration` 的 EWMA 分桶校准，诊断记 `tokenRatio`。
- 必要内容超限：`overHard=true` 落降级日志；发送前仍超 → `context_overflow` **拒发**，不砍权限/人格/本轮请求。

### M2 水位与滚动压缩

- `contextLifecycle.js`：soft 0.70 / hard 0.85 / target 0.60，冷却 3 轮，最少 8 轮才压，最近 6 轮原文不动；`hard≤soft` 或 `target≥soft` 时回落默认。
- 压缩顺序：大工具输出（≥600 token）→ 最旧轮次；`correction/todo/goal/boundary/pinned` 受保护。
- 摘要：复用 `rollupTurns` 的金额/日期/人名/否定词完整性校验；**分批 20 条**（一次 200 条必然校验失败，等于没有摘要）；失败只归档、不标"已压缩"。
- `MAX_TURNS` 到顶时**批量搬到 16 轮**，不是每轮搬 1 条（实测 120 轮从 90 次碎片压缩降到 14 次）。
- 摘要注入只在回忆/延续线索时进池，且要过相关性闸；否则"随便聊聊"会把整段摘要拖回来（P15-TG 回归即此）。

### M3 归档、恢复与一致性

- 段格式：`segments/<sessionHash>/0001-<hash>.jsonl`，每行带 `prev/hash` 链；`manifest.json` 用 `version` 单调递增做 CAS。
- 先写段（tmp+rename）→ 再写 manifest → 才从热窗口移除。归档失败：`turns` 一条不减，`overflow=true`。
- 恢复：`recallArchived({ids|from/to|q|terms, limit≤200})`，读取前 `allowedScopes=[当前scope]`，跨用户/跨 scope/跨会话一律 0 结果。
- 失效链：纠错后便签就地更新、含旧值摘要标 `stale`、恢复时按"相似≥0.6 且数字不同"过滤已被替代的片段。
- 删除：`redact` 同时清热窗口与归档段；测试验证删除后按关键词恢复为 0。
- 兼容：旧会话文件无 `rollups/archive/compact` 字段时按空处理，首次压缩自然升级，不升 `version`；legacy 模式 `contextPlan=null`，行为逐字节保持。
