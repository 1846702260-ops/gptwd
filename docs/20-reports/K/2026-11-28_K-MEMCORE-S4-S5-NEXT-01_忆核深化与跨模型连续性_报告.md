三、清空后为什么会复活
仓库无一键清空，只有逐条 purge。即使逐条清空全部原子，仍有九条路径会让她念出旧事：turns.jsonl 无清理代码且每轮无条件注入（最高风险）；people.json 未删条目按 ungoverned 放行；archive 每日 md 不被 redact 触及且七天内注入；working segments 只按原文字串命中、改述不命中；events 只写黑名单原文留盘；mem.json 轮转快照非逐条清空不走擦写；backup 与 NAS 包恢复即带回；restore 遗留 pre-restore 与 workspace.old 整份留存；墓碑仅存 id 与十六位非加密指纹，旧墓碑认不出正文，同文本重写可绕过。
Z 只读显示 memv2 仅 3 原子、旧分片 0 条，memv2 干净不代表九条路径干净。本轮只报告代码层可能性，未读取未验证真实残留。

四、外部研究与方案
行业重心已从检索转向写路径巩固。微软仿生记忆架构实证显示单纯去重巩固是质量主导，激进聚合摘要反破坏事实细节；并指出固化循环本身是故障源，各家巩固前后一致性校验与审计回放普遍薄弱，这正是我们链式治理账本与删除账本的现成优势。
方案比较：S4 建议 memv2 本地增量而非整包引入外部框架，因整包会形成第二真源、运维重、与硬约束冲突，机制可学而框架不必引；S5 建议 memv2 原生导出导入契约而非第三方 MCP 记忆服务，因私密记忆不得托管外部。可行性证据：memv2 原子已具备文本、类型、重要度、作用域、有效期、后继、版本、证据指针与墓碑，外部契约八字段已有七个，只缺签名。
