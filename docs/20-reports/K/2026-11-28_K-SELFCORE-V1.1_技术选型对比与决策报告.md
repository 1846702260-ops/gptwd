## 二、先说结论：V1.0 确实是静态状态面板

### 2.1 八条硬伤（自我否决，不辩护）

| # | 缺陷 | 证据（代码级） |
|---|---|---|
| 1 | 无状态 | `profile()` 每次从零重算，无跨轮累积；无任何账本 |
| 2 | 置信度是拍脑袋 | `evidenceProfile.js` 硬编码 `confidence = 0.9/0.85/0.6/0.5/0.3/0.2` |
| 3 | 无预测误差闭环 | 只事后读回执，无"事前预测→事后对照" |
| 4 | 无校准度量 | 无 Brier/ECE，无法回答"我的信心准不准" |
| 5 | 无可靠性度量 | 只有单次判定，无重复一致性；单次成功即记为 verified |
| 6 | 无发展轨迹 | 无法回答"我比上期多会了什么" |
| 7 | 无元认知偏差信号 | declared 与回执冲突只标 `unverified`，浪费了最有价值的自知信号 |
| 8 | 无主动边界探测 | 只能被动等回执 |

### 2.2 第 2 条为什么是**设计错误**而非"近似处理"

2025-12 的前沿实证（alphaXiv 2512.24661）用三组实验测得：

- 单步：BigCodeBench 1140 题，执行前先估成功率；
- 代价学习：9 个连续工作合同，成功 +1、失败 −1，观察是否修正信心；
- 多步：SWE-Bench Verified 499 题，每次工具调用后重估信心（行动预算 70 步）。

结论：**所有情境下系统性过度自信**，且**即便给予了学习机会也不自我校正**。

> 这意味着：我给 `confidence: 0.9` 这个动作本身，复刻的正是被实证否定的那种"主观乐观"。自核一旦输出这种数字，等于把"我觉得我行"包装成"统计上我行"。

因此 V1.1 的处理不是"调小常量"，而是**取消常量**：无经验样本时 `confidence = null`。

### 2.3 另一条独立证据：能力 ≠ 可靠性

τ-bench（Yao et al., 2024）提出 `pass^k`（同一任务跑 k 次全过才算过）：

| 指标 | gpt-4o 零售域 |
|---|---|
| pass^1（单次） | ≈ 61% |
| pass^8（八次全过） | ≈ 25% |

2026-09 的 Consistency Gap 研究（AppWorld 168 任务 × 5 次）同样显示：平均 ≈77% vs 五次全过 ≈53%，差 24.4 个百分点。

> 意味着：V1.0 的"最近一次成功 → verified → 我可以"是**系统性自我夸大**的机制。V1.1 必须同时报 pass^k。

### 3.1 逐项理由

**`registry.js`（复用，不改）**
工具注册表是单一真源（`builtinEntry/mcpEntry/REGISTRY_DIGEST`，未登记一律 L4），设计正确、边界清晰。G 指令禁止无意义重写成熟组件——此组件无短板，动它只有风险没有收益。**决策：零改动。**

**`toolgate.js`（复用 + 旁路补强，不改本体）**
九步执行、shadow/enforce 双模、审计链完备，是行核核心。唯一缺陷：**执行回执不含时间戳**（V1.0 风险清单 B2）。但直接改回执结构属**跨核契约变更**（行核对外接口），须 G 裁决。**决策：本体不动；自核侧用 `normalizeReceipts` 容错并显式标注 `atKnown=false`，不假装新鲜。**

**`self-model.js`（复用，只读，不改权威字段）**
它是 persona 的能力权威真源（`noteCapability` 带 state/basis/evidence）。V1.0 只加了可选 `setSelfCore` 钩子，未写入任何事实。**关键判断：若让自核回写 `verified` 或 `confidence` 到 self-model，属权威数据源迁移，必须 G 裁决。本轮不写。**

**`evocore.js`（复用 + 融合）**
已有 `capability_gap` 处理与 `createSkillLab`（DryRun，APPROVED 前不进正式目录）。自核只需 `toEvoGaps()` 输出缺口形状，**不建第二套训练系统**——这是任务书 M4 的硬约束，本层严格遵守。

**`selfState.js` / `evidenceProfile.js`（V1.0 自建，改造）**
作为"读快照→判六态"的分类器，逻辑本身没错，错在**止步于此**。决策：保留六态分类语义（已被测试固定、与 R PoC 对齐），但**其上叠加时间、校准、可靠性、轨迹四层**。

## 六、V1.1 实施内容（已在授权范围内完成）

### 6.1 新增模块

| 文件 | 职能 | 关键设计 |
|---|---|---|
| `src/selfcore/calibration.js` | 校准账本 + Brier/ECE/bias | **样本不足返回全 null**，绝不编数 |
| `src/selfcore/reliability.js` | pass@k / pass^k / 可靠性缺口 | n<k 时 pass^k=null，不作外推 |
| `src/selfcore/trajectory.js` | 状态迁移 + 元认知四类信号 | 只描述迁移，不叙事 |
| `src/selfcore/index.js`（改造） | 统一出口扩展 M7–M9 | 保留全部 V1.0 API，向后兼容 |

### 6.2 三个"动态"机制

**① 预测-验证闭环（M7）**

```
predict(capability) → { p, basis, sufficient, bias }
   ↓  执行
observe({capability, predictedP, actualOk})
   ↓  累积
calibration() → { brier, ece, bias, verdict }
```

`predict` 的诚实之处：冷启动时 `p = null`、`basis='cold_start'`，并明确说"样本 n=0 未达最小 8，不给概率估计"。**它宁可承认不知道，也不给一个好看的数。**

若历史显示过度自信（`bias > 0.1`），`predict` 会**主动下调**：`adjusted = rate − max(0, bias)`。这是唯一允许"自我修正"的地方，且修正依据是可复算的统计量。

**② 可靠性（M8）**

按能力分组算 `mean / pass@k / pass^k / reliabilityGap`。`reliabilityGap = mean − pass^k` 越大，说明"看着行、用起来不行"。

**③ 轨迹与元认知（M9）**

- `trajectoryOf()`：比对快照序列，产出 `gained / degraded / appeared / disappeared` 事件与 `netVerified`。
- `selfKnowledge()`：把"自述 vs 证据"的错位显式命名四类——

| 类型 | 含义 | 价值 |
|---|---|---|
| `overconfident` | 说会，但回执失败 | 高估，须下调 |
| `underconfident` | 说不会，但回执成功 | 低估，可上调 |
| `illusory` | 说会，但零证据 | **幻觉风险最高** |
| `honest` | 说会且已验证 / 说不会且确实不会 | 自知准确 |

`deviationRate` = 错位条目 / 总声明条目，可作为"自我认知准确度"的单一指标。

### 6.3 存储定位（重要，涉裁决）

校准账本与快照序列均为**派生缓存**：

- 全部内容可由"预测记录 + 执行回执"**重放重建**；
- 不承载任何不可再生事实；
- 默认**纯内存**，进程结束即失，**不产生新的持久化写入**。

因此在架构上**不构成第二套事实真源**，未触碰 memv2 唯一真源边界。若 G 批准持久化，注入 `fileStore` 即可，不改上层语义。

## 七、需 G 裁决事项（4 项）

> 以下 4 项本轮**均未擅自实施**，仅提出方案。

### 裁决 1：校准账本是否允许持久化

- **现状**：纯内存，重启即失。轨迹跨进程不可见。
- **方案 A（当前）**：维持内存。零风险，但"持续自我认知发展"跨会话不成立。
- **方案 B**：落盘为 `selfcore/calibration.jsonl`，追加写、可重放、可随时删除重建。
- **K 建议**：**B，但定位为"可丢弃缓存"**，并在文档与代码双处标注"派生数据，非事实真源，删除不损失任何不可再生信息"。若 G 认为任何新增落盘都需更高门槛，则维持 A，接受"跨会话无轨迹"的限制。
- **影响面**：`selfcore/` 内新增 1 个数据文件；不触碰 memv2。

### 裁决 2：`self-model.js` 是否接受自核回写

- **现状**：只读，V1.0/V1.1 均不写。
- **方案 A（当前）**：保持只读，自核结论只存在于派生层。
- **方案 B**：允许自核把 `verified/confidence` 回写为 self-model 的字段。
- **K 建议**：**维持 A**。理由：回写即权威数据源迁移，且 self-model 是 persona 的语义域（"我声称我会什么"），与自核的"证据上我会什么"是不同语义，混写会污染两者。若将来需要，应新建独立字段而非覆盖原字段。

### 裁决 3：`ToolGateway` 回执是否补 `at` 时间戳

- **现状**：回执无时间戳（风险 B2），自核只能标 `atKnown=false`，导致"证据过期/新鲜"判定降级至 0.6 置信或不可判。
- **方案 A（当前）**：自核侧容错，不改网关。
- **方案 B**：在 `toolgate.done()` 的 base 记录中加 `at: Date.now()`。
- **K 建议**：**B，但需 G 批准**。理由：这是**跨核契约变更**（行核对外回执结构），虽只增一个字段、向后兼容，但按 G 指令必须报批。此改动收益很大——它是"证据过期"与"校准时间序列"两项能力的前提。
- **若不批**：自核的 stale 判定长期停留在"时间未知"，校准只能按条序而非按时间。

### 裁决 4：是否引入 ReMe 式结构化经验（P2）

- **现状**：未引入。
- **K 建议**：**暂缓至 P2**，且前置条件是"用知遥自有任务独立复现其自报增益"。理由：R 报告标注其 SOTA 为自报、仅 2 个 benchmark、无独立复现；直接采信违反"语义相似不是事实证明"的纪律。

## 九、边界与未做事项

**未做（明确）**

- 未部署、未改生产、未改人格核心、未恢复历史记忆；
- 未调真实模型（费用 0），`predict` 的真实效果**未在生产数据上验证**；
- 未引入 LangGraph / ReMe / ConfTuner / KnowSelf 任一实现；
- 未让自核回写 self-model；
- 未新增任何持久化写入（默认纯内存）；
- 4 项裁决事项**均未擅自实施**。

**已知局限（如实）**

1. 校准需要足够的"预测-结果对"才有意义。当前生产回执无时间戳，历史数据也不含先验预测，因此**冷启动期会持续返回 `sufficient:false`**。这是设计意图（宁可不说），但需 G 知悉：短期内自核仍会说"我还不知道我准不准"。
2. `reliability()` 依赖 `toolgate.recent()`，其容量上限 500 条，长周期可靠性会因窗口截断而失真。
3. M9 轨迹默认依赖内存快照（50 条上限），跨会话不成立，除非裁决 1 通过。

## 十、结论

| 判断 | 结论 |
|---|---|
| V1.0 是否静态面板 | **是**，八条硬伤，本报告不辩护 |
| 现有组件是否该复用 | **多数该复用**（registry/toolgate/self-model/evocore 均成熟），盲目重写是错 |

| 空白区怎么办 | **自主创新**（校准/可靠性/轨迹三件），R 已确认业界无成熟件 |
| 是否已达成"动态自我模型" | **机制层面是**（预测-结果闭环 + 校准 + 轨迹 + 偏差信号）；**数据层面待**（需真实预测样本 + 裁决 1/3） |
| 是否越权 | **否**，4 项敏感改动全部待裁决 |
