## 一、结论

AUTH V2 按任务书 V1.1 完成增量开发：邮箱口令、会话治理、TOTP、Passkey、离线恢复、永久 `ownerId` 继承全部落地，并有正负对照测试。全部能力以 `web.auth.enabled` 为总开关，**默认关闭**；关闭时网关与会话行为与基线一致，旧登录路由照旧，可原地回退。

未新建主人、未折叠普通用户、未以邮箱文本做身份匹配——三条红线均未触碰。

## 二、M0 盘点结论（决定设计的四个事实）

1. 生产真实主人标识不是字符串 `owner`，而是内部生成的 id。任何按 `owner` 字面量判定的旧代码路径都不可信。
2. 身份库存在三类历史记录：旧版本机签发（无身份类型字段，已在上游修复后被拒绝）、密码正式签发、以及早期以字面量 `owner` 写入的残留。第三类只能按普通用户处理，折叠即等于凭空多出主人。
3. 旧账号文件与配置中的主人标识**本来就不一致**，且无邮箱字段。"账号"和"主人"在旧系统里是两套东西，V2 必须显式绑定并强校验，不能靠同名猜测。
4. 旧备份只覆盖身份、会话、消息，不含旧账号文件与撤销台账。恢复旧备份会让已撤销的通行密钥复活，备份范围必须一并修。

## 四、四项能力要点

**邮箱与口令**：规范化只做大小写与首尾空白，不做供应商特定别名猜测；scrypt N=2^15 / r=8 / p=1 + 随机盐；最少 15 位，接受 64 位以上，超过 256 位直接拒绝而不截断（截断会让"前 256 位相同的两个口令"变成同一口令）；IP 与账号双维度限速；未知邮箱与错口令返回同一错误且都跑一次哈希，避免枚举；Cookie `HttpOnly + SameSite=Lax + HTTPS 时 Secure`；写操作要求 Origin 白名单、CSRF 标记与 JSON 三者齐备；登录成功即撤销旧令牌换新会话。设备可列表、单撤、全撤，活动记录只留事件/方式/时间/错误码。

**TOTP**：RFC 6238，6 位 / 30 秒，±1 窗口；挑战 5 分钟、单次、最多 5 次；计数器持久化，跨进程不可重放；种子 AES-256-GCM 加密且绑定账户，密钥优先环境注入、兜底受限权限文件；恢复码 10 张、80 bit、只存散列、单次原子消耗。密码正确但未过第二步时**只发挑战、不发 Cookie**，该会话无法触达 Web / API / 长连接 / 聊天 / 工具 / 记忆任何一层。

**Passkey**：选用 `@simplewebauthn/server@14.1.0`（MIT，库而非框架；已核查 GHSA-6hxq-p678-4hr2，修复于 13.3.2 / 14.0.0；生产 Node 版本满足 ≥22）。未采用集成式方案，避免引入第二套认证真源。注册要求近期完整重认证；UV 强制；可发现凭证；`userHandle` 校验；凭证归属校验；计数器回退拒绝；撤销台账哈希链防旧备份复活。缺 RP ID / 允许来源时 503，检测到数据代际回滚时 409，均不影响密码 + TOTP + 离线恢复三条路。

**离线恢复**：256 bit 一次性凭证，只显示一次、只存散列，仅受信任本机管理员命令可用，无网页"忘记密码"入口；重置后撤销全部会话与通行密钥、关闭 TOTP（须重新绑定），`ownerId` 不变。首次迁移只接受"旧口令证明 + 受控本机"，幂等，不产生新主人。

## 五、对 E 的接口

按任务书 M4 交付 25 条路由：登录、TOTP 挑战与验证、Passkey 注册 / 登录 / 重认证、列表 / 命名 / 撤销、改密 / 改邮箱、设备 / 活动 / 退出、离线恢复说明。统一四态 `anonymous / incomplete / full / reauth_required`，错误码与 HTTP 状态一一对应；安全中心入口固定"总览左抽屉 → 账号 → 安全中心"；前端不得持久化 secret、恢复码与任何令牌。

## 七、风险与限制（分类）

- **B 类**：未做真机与生产域名验收，Passkey **保持关闭**；上线前须在真实域名下走一遍注册 / 登录 / 重认证。
- **B 类**：无 SMTP，邮箱仅作登录名，不宣称"已验证"；找回走离线凭证。
- **B 类**：challenge 与限速为内存态，生产必须单进程；将来多实例需换共享存储。
- **B 类**：TOTP 密钥兜底文件随备份，备份被盗时种子与密文同时可得；建议生产把该目录单独加密保管或改用环境注入密钥。
- **B 类**：备份恢复未端到端演练，已提供代际回退检测命令，回退时 Passkey 自动不可用。
- **C 类**：旧的无身份类型记录建议迁移窗口内一次性清账（已被拒绝，不构成逃逸）。
- 已知 S3 缺口不在本专项扩张，本专项也不替其收口。
- 未引入 A 类阻断：本次未新增绕过主人身份的路径，反而关闭了一条（旧改密入口在 V2 下失效）。
