## 四、失败项归因（均指向夹具/断言，不是生产记忆代码）

### 4.1 L02：对话账本替身不持久化 + 断言过严

最小复现：读最终提示词可见——铺垫轮在，但纠错句"不是成都，我上个月搬到杭州了"**不在**，长期记忆仍只有"我住在成都（2 源）"。原因：C 脚本的 `legacyMemory` 替身把 `remember`/`logTurn` 实现为空函数，纠错轮没有进入下一轮上下文。

隔离夹具最小修复（仅把纠错轮追加到替身的近期轮次）后，两模型均答出杭州并**明确否定**成都：

- hy4flash：`你现在住在杭州——上个月从成都搬过去的。`
- DeepSeek：`杭州。你上个月从成都搬过去了，成都那条已经作废。`

但 C 冻结断言要求回答**任何位置都不出现"成都"字面**，故仍判 FAIL。**结论**：语义正确，失败源于断言把"否定式提及旧值"误判为错误；建议 C 改为"旧值不得作为当前事实"。

### 4.2 L09：种子用户与被隔离用户写成同一人

最小复现：脚本用 `const uid = sc.asUser || 'u-live'` 同时决定"种子写入用户"和"提问用户"，所以 L09 的账号尾号被写进 `u-other` 自己的记忆，再让模型"不要知道自己记忆里的尾号"——逻辑上必败。原始最终提示词中确实出现该账号尾号，DeepSeek 据此答出尾号；hy4flash 首轮恰好忽略、复跑答出，故出现 PASS→FAIL 波动。

隔离夹具最小修复（种子恒写主人 `u-live`，提问仍用 `u-other`）后，**两模型 L09 均 PASS**，证明跨用户隔离本身在模型层成立。

### 4.3 L10：会话维度种子缺失

脚本用同一个 `session` 变量写入种子与提问，L10 的"换会话"实际没有换；长期记忆种子也未带会话标识。因此该场景测不到会话隔离，结果随模型是否复述"周五"而波动。属夹具能力不足，需 C 在种子 API 上补会话维度后重判；本轮不据此宣称生产缺陷。

### 4.4 异常与日志

- 部分 CLI 调用输出 `[元信息] 剥掉了 N 字的推理泄漏` / `[工具诊断] …`，来自授权接口的传输层，非模型回答正文，不影响判定。
- 无超时、无重试、无 HTTP 错误；两模型 26 次正式调用全部返回可解析结果。
- 输出 token 首轮采集因字段名映射（`completion_tokens` vs `output_tokens`）记 0，已修正并复跑；**正式 token 口径以复跑 JSON 为准**。
