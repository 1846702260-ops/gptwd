## 4. 一处自我纠正（必须记录）

执行中我一度判定 `.backup.lock`（内容 `825425`，该 PID 已死）是"残留锁会导致下次备份 `die 4`"，据此删除并写入结论。

**实测后纠正**：`take_run_lock()` 用的是 `flock -n 9`（文件描述符锁），**进程退出即释放**，磁盘上的锁文件只是 PID 文本残留，不参与互斥判断。证据：05:06 的 dry-run 在锁文件存在（内容为已死 PID `825425`）的情况下正常取锁运行、退出码 0。

- 影响评估：删除该文件时持有进程已死，**无副作用**；删除后两次运行均正常。
- 结论修正：**锁机制无缺陷**，我最初的"必须清理否则 M3 会挂"判断是错的，已在报告中撤回。`flock` 语义下锁文件长期存在属设计行为。
