# 07 · 真机验收缺陷修复：安全中心重验证弹层不可见

发现时间 2026-11-26 22:59｜修复上线 2026-11-26 23:02｜坐标 `a25dd0c`

## 1. 现象

主人真机点「修改邮箱 / 密码（需重新验证）」后，**页面无任何反应、无任何提示**。

## 2. 根因（源码定位，非猜测）

`packages/web-v1/src/security/SecurityCenter.tsx` 的三个缺陷叠加：

| # | 缺陷 | 后果 |
| --- | --- | --- |
| 1 | 重验证弹层以普通卡片形式渲染在 `<section>` 末尾（位于「身份与渠道」卡之后，即第 7 屏附近），不是浮层 | 点按钮后弹层出现在屏幕下方视口外，观感等于"没反应" |
| 2 | 全局 `error` / `notice` 渲染在页面**顶部** | 即便提交失败，提示也在视野之外，等于"没提示" |
| 3 | `doReauth` 无论成败都立即 `setReauthFor(null)` | 失败时弹层瞬间消失，用户来不及看到原因 |

后端无问题：`/api/web/auth/reauth`、`/password`、`/email` 均存在且逻辑正确（`#requireOwner(token, { reauth: true })` 要求先重验证，前端顺序正确）。

## 3. 修复内容（仅前端 1 文件，+62 / −16）

1. 重验证与撤销确认两个弹层改为 `position: fixed` 视口浮层（`zIndex 120`、半透明遮罩、`maxWidth 460`、`maxHeight 86vh` 内部滚动），点遮罩关闭，内容区阻止冒泡。
2. 弹层内就地渲染 `error`，失败时**保持打开**，只有成功才关闭。
3. 确认按钮增加 `处理中…` 与忙碌禁用，避免重复提交。
4. 账号卡片新增就地结果反馈：成功后显示「已完成：邮箱 / 密码已更新，下次登录请使用新信息。」
5. 点按钮前先做本地校验，不再让空输入进入重验证：
   - 新邮箱与新密码都为空 → 「请先填写「新邮箱」或「新密码」，再点这里。」
   - 邮箱格式不合法 → 立即提示
   - 新密码不足 8 位 → 立即提示
