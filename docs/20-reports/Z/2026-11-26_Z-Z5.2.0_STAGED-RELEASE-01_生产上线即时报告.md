## 三、发布过程中发现并修复的问题

### 依赖缺失导致首次部署失败（已修复）

首次执行 `deploy-linux.sh --redeploy` 时门禁 9 项通过，但健康检查失败，服务进入重启循环并被脚本自动回滚产物。根因：新版本新增依赖 `otplib@13.6.0`，生产 `node_modules` 仍为旧版，`src/auth/totp.mjs` 导入失败 → `ERR_MODULE_NOT_FOUND` → 进程退出。

处置：`npm ci` 两次失败（`Exit handler never called`），最终定位真因是 **`/etc/profile.d/proxy.sh` 残留死代理 `<DEAD_PROXY>`**，导致 npm registry 请求失败。清代理后 `npm ci` 成功（308 packages，rc=0），全部依赖版本与 `package.json` 一致，`otplib` 13.6.0 实测 `generateSecret`/`generateSync`/`verifySync` 三态正确（错误令牌 `{valid:false}`）。

> 此根因与 bridge 热修 `PROXY_GUARD` **同源**：生产机 profile.d 里的死代理会让继承环境的手工进程走代理。本次由发布流程暴露，热修本身已带该防护。

### 部署脚本在 `--redeploy` 模式下不装依赖（流程缺口）

`deploy-linux.sh` 的依赖安装条件是 `git diff --quiet "$OLD_HEAD" HEAD -- package.json package-lock.json`，而 `--redeploy` 时 `OLD_HEAD == HEAD`，diff 恒空 → 永远不装依赖。**若目标版本新增依赖，`--redeploy` 必然启动失败。** 本次已手动补装，但该缺口未修，建议后续补入脚本。
