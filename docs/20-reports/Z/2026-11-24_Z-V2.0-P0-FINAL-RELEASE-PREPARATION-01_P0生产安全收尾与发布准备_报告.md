## 二、M1｜本机免密主人身份（A1）

### 2.1 机制核实（区分 OS 本地认证与应用层身份）

- **OS 层**：生产以服务管理器直接运行 Node 进程，无独立服务账号、无 socket 授权。本机任何可访问监听端口的进程都等价于“本机运维身份”——这是操作系统权限问题，不是应用层身份。
- **应用层**：旧代码有两条“因来源是本机而获得更高身份”的路径：①本机直连免访问口令（默认开）；②本机 + 已过门禁时免密自动签发主人级设备令牌。第 ② 条即“本机 = 主人全权”，是本轮核心。
- **信任来源**：判定依据为源地址回环 + 主机名白名单 + 无代理头。分享链接与隧道均从本机转发，仅凭地址无法区分，故两条路径必须同时关闭。

### 2.2 生产实测（只读）

| 项 | 实测 |
|---|---|
| 免访问口令开关 | **显式关闭** → 第 ① 条路径当前不可用 |
| 免密登录开关 | **未配置** → 第 ② 条路径当前不成立 |
| 代码默认值 | 仍为“默认开/可开” → **默认不安全** |
| 服务管理器环境注入 | 无环境文件，配置全部来自运行配置文件 |

**结论（修正上一轮口径）**：生产 A1 **当前不可利用**（配置层已关闭），但风险未消除：代码默认值仍是“开”，任何配置重写、配置丢失或新部署都会退回旧默认；且本机任何进程都能读到明文访问口令（见 M2），“绕开第一层门禁”的间接路径仍在。

### 2.4 上线需改变的配置/代码

- **配置层**：免访问口令开关保持/显式关闭；免密登录开关不得出现（候选已强制忽略）。
- **代码层**：部署候选后默认值改为关闭、免密登录强制关闭、无身份类型的旧主人令牌拒绝，三层同时生效，不再依赖配置正确性。
- **如何安全恢复合法主人访问**：账号 + 密码登录。**不得**以“重新打开免密/免口令”作为回滚手段——那会把 A1 直接退回未修复状态。

### 2.5 登记缺陷（可观测性，不改变安全行为）
