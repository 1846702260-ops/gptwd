## D-04【新增·中】前端 WS 层 `auth_required` 不跳登录页，把错误码直接挂给主人

### 位置

`packages/web-v1/src/ws.ts` 第 54 行（错误文案回退）与第 87–99 行（auth_required → ApiError）

### 问题

- HTTP 层已正确处理：`api.ts:85` 对 `no_identity` 且非 session 路径做跳登录；`Chat.tsx:820` 对 `code==='auth_required'` 置 `setNeedLogin(true)`
- 但 **WS 层**收到 `auth_required` 后抛出的 `ApiError`，在 `ws.ts:54` 落到 `HUMAN[e.code] || '出了点问题（' + e.code + '）'`——`HUMAN` 表**没有 `auth_required` 条目**，总览页（非 Chat 路由）没有 `setNeedLogin` 分支 → 主人看到裸错误码「出了点问题 (auth_required)」，无路可走

### 生产实证（主人 iPhone 截图）

- 截图 1（14:29）：PWA 打开直接显示「出了点问题 (auth_required)」，停留在主界面而非登录页 —— WS 层错误直接渲染
- 截图 2（08:32）：点击聊天圆球后才进入登录页 —— Chat.tsx 有 auth_required→needLogin 分支，总览页没有，**同一缺陷的两面**
- iOS 密码自动填充弹「通过 14***@qq.com 的密码登录 duckdns.org」属系统行为，非缺陷；「当前浏览器或服务器端不支持通行密钥，请用密码登录」为 `passkey.enabled=false` 的正常提示

### 建议修复

1. `ws.ts` 的 `HUMAN` 表补 `auth_required: '请先登录。'`；
2. WS 层收到 `auth_required` 时统一触发与 HTTP 层一致的跳登录逻辑（或在总览页等所有首屏入口补 `setNeedLogin` 分支），确保**无令牌/令牌失效时任何页面都直达登录页**，不再裸显错误码。

### 修复要求

- 不改变认证判定逻辑与 Cookie 签发行为；仅前端路由/文案
- 补测试：WS 返回 401 `auth_required` 时首屏渲染登录页而非错误文案（`app.test.tsx` 已有 HTTP 层同类测试可参照）
