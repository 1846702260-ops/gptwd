三、三项修复
经验记忆隔离：写入侧四条路径都绑定 ownerId 与 visibility；读取侧在打分前先按主体过滤，历史无归属、半新格式、未知主体一律不注入，且不改动、不删除旧记录。三人私有标记两两互不串读，合法主体仍能读到自己的经验，不是靠关闭全部记忆换来的假通过。

归档分片隔离：归档改为按 uid 分目录，摘要生成阶段就按主体聚合；无 uid 历史行进隔离区，永不注入；旧顶层归档保留但不再被读取；八种路径穿越写法全部被拦；重启后隔离仍生效。

旧入口降级：我用一个假模型服务器抓取真实请求体来判定，而不是靠无模型时的 500 猜。配了凭证时无凭证请求返回 403 且不触达模型；合法主人路径仍挂载九件工具、仍能读到自己档案；未配凭证时旧接口降级为受限陪伴，请求体里根本没有工具字段，也读不到任何主人记忆，且不写入账本。工具是被结构性移除的，不是提示词劝阻。

五、S0-B
实测两种形态。配置 ownerId 的生产形态下，两个全新客户端拿到的 userId 完全相同且等于配置值，不存在第二个主体。未配置形态下，两个客户端能拿到两个不同的非主人身份，于是成员与成员之间的隔离可以在真实链路上验证：互不串读、主人预置记录不被读取也不被改写、重启后仍隔离、B 访问 A 的会话返回 404，全部通过。因此 S0-B 仍然阻断，但阻断边界已从笼统的不可测收窄为一句可证伪的话：生产形态没有成员，未配置形态没有主人，主人与成员并存这一格不可构造。叠加 P0 的 U1 与 R3 也不能解决，它们让主人判定更严，不产生第二个主体。
