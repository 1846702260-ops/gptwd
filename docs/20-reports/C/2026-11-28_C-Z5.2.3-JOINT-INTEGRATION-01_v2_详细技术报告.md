## 1. 取包方法纠错（这是我上一版的判断错误）

上一版判 E 不可达，依据是 `list-nodes --space-id` 返回 `12607 permission denied (role=invalid)`。**结论错了，取法错了。**

权限模型的事实：共享空间不在本账号 `list-user-spaces` 里是**正常现象**；按空间维度列目录必然被拒。正确姿势是**按节点 ID 直接 `node-info` 逐层下钻**。

实际走通的路径：

```
node-info 1w1kg8e5vy866L9J0xU5RB   (C 侧，已知可读)
  → parentId = PxQyIdb65dPiDQRvzraJ8G  ("知遥AGI-工作区" 根，13 个子节点)
  → 2lu5DjkasAZsFX2VIaM8EH (E 侧, 10 项)
  → 0CLhTiuWl8JC9oawKye9OC (E-CROSS-DEVICE-CHAT-SYNC-01, 9 项)
```

**踩到的第二个坑**：截图给的链接把 `I` 写成了 `l`——
`YSkfQjbLPD` **`l`** `D7sa…` 实为 `YSkfQjbLPD`**`I`**`D7sa…`；`2lu5DjkasAZsFX2V`**`i`**`aM8EH` 实为 `…V`**`I`**`aM8EH`。
节点 ID 大小写敏感，错一个字母就是 `11510 node index not found`。而报错文案是"index not found"，读起来像"这个节点不存在"，实际是"这个字符串不是节点"——两者我一开始没分清。

**教训固化**：以后跨侧取件，先按父节点的 `parentId` 逐层下钻拿真实 ID，不要用别人给的链接里的 ID 直接当权威值。

  + git apply E-CROSS-DEVICE-CHAT-SYNC-01.patch   → 干净通过，零冲突

E 基于 `e1dea27`，与生产 Z5.2.2 的改动（`index.js` +4、`research.js` 等）不重叠，所以 `git apply` 无需人工解决。

**为何排除 6 个 `frontend/` 文件**：它们是 `chat_sync_browser.json`、`chat_sync_http.json` 与 4 个 `verify/*` 脚本——E 的取证产物。放进产品树会让每次 clone 都携带别人的运行日志，也会让"产品 diff"里混入非产品内容。E 的 patch 把它们放在 `frontend/` 前缀下，本意应该就是"这些是证据不是产品"，只是被打进了同一个 patch。

## 4. E 的实现质量（读代码核对）

### 4.1 身份隔离是结构性的

事件走 `UserEventBus`，`publish(userId, …)` / `subscribe(userId, …)`。频道由数据身份决定，**不存在"忘了判断归属"的可能**——这是这轮最值得肯定的设计选择。对比一下：如果做成一条全局广播 + 订阅端过滤，那每一处都得记得过滤，漏一处就是泄露。

### 4.2 回声抑制的坐标系是对的

`turn.state` 带 `clientMsgId`，发起端据此忽略自己的回声；`delta` 节流 120ms。这两条合起来解决的是"两端都说自己在生成、同一句话重复两遍"这类最容易出的丑。

### 4.3 通知不阻断主流程

`#notifySessionChanged` 在锁外调用，异常 `try/catch` 吞掉。方向正确：通知监听坏了不该让主人建不了会话。

### 4.4 断线恢复用的是真机制

总线自带 `seq` + 环形缓冲（`maxPerUser` 200、TTL 10min），端点读 `last-event-id` 重放。**不是轮询兜底，也不是"重连就重拉全量"**。我实测：断线期间改名，重连带 `lastId=1` 拿到 `renamed`。
