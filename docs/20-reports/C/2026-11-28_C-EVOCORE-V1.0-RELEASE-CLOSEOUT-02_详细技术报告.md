### 3.1 复现

用真实形态构造（`style`/`script` 标签以拼接方式构造，避免与页面标记混淆）：

| 形态 | 修复前正文 | 判定 |

根因：`stripBlocks` 的 `/<(script|style|noscript|svg|iframe|form|nav|header|footer|aside)[\s\S]*?<\/\1>/gi` 要求成对闭合。截断与"内部含闭合串"两种真实情形都绕不过去。

### 3.2 修复

三层清理，顺序不可反：

```js
① 成对删除（原逻辑保留）
② 删未闭合块：从残留开标签吃到「下一个闭合标签」或文末，循环最多 30 次
③ 删残余 CSS：{...} 规则块、--var: value;、@media 头、孤立花括号
```

关键约束：**② 只在还能找到开标签时动手**。若页面是正常的 `<style>…</style><p>正文</p>`，成对删除已清干净，②找不到开标签，不会误删后面的正文。这条有专项测试（R1-5：成对块之后的 `Following paragraph survives.` 必须保住）。

③ 的取舍：正文里出现 `--var:` 或 `{...}` 在自然语言中几乎不可能，删除安全；但**不删**散文里的普通冒号（R1-7：`Note: this paragraph…` 保留）。

`extractText`（兜底路径与 title/hidden 提取）同步套用 ③，避免另一条路径漏网。

## 四、缺陷 ② CSS token 触发密钥误判

### 4.1 复现

原判据是单条正则：`/(api[_\s-]?key|token|secret)\s*[:=]\s*\S{8,}/i` —— 只要 `token:` 后面跟 8 个非空白字符就报。

| 输入 | 修复前 | 说明 |
| --- | --- | --- |
| `--md-token:rgba(0,0,0,0.8);` | **误判** `token:rgba(0,0,0,0.8);` | 设计系统变量 |
| `:root{--token:12px;--token-color:#ffffff}` | **误判** | 尺寸/颜色变量 |
| `.x{--space-token:1rem}` | 未命中 | 值太短（空格隔开） |
| `api_key: sk-live-abcdef1234567890` | 命中 ✓ | 真密钥 |

误判后果不是"多一条提示"，而是 `detectDirective` 判可疑 → `untrusted_directive` → **整页被拒**，学习目标直接 `rejected`。真实页面普遍带设计系统变量，这是 Z"真实网页留出学习 0/4"最可能的直接原因之一。

### 4.2 修复

拆成"抓候选 + 按值判定"两段：

```
SECRET_CANDIDATE: (强键名|token|secret)\s*[:=]\s*["'`]?(值)
  ↓
looksLikeCssValue(值) ? 跳过
  ↓ 否则
强键名 || looksLikeSecret(值) ? 报
  ↓ 另
BARE_SECRET 单独扫一遍裸密钥（无键名）
```

**CSS 值识别**：`#hex`、数字+单位（px/rem/em/%/vh/vw/s/ms/deg/fr…）、纯数字、CSS 函数（`rgba(`/`var(`/`calc(`/`blur(`/`translate(`/`gradient(`…）、CSS 关键字（`none`/`absolute`/`solid`/`inherit`…）、两词小写组合。

**密钥形态识别**：`sk-`/`pk-`/`rk-` 前缀、`ghp_`/`gho_`/`ghu_`/`ghs_`/`ghr_`、`github_pat_`、`xox[baprs]-`、`AKIA` + 16 位、JWT（三段点分）、`sk_live_`/`sk_test_`、长度 ≥20 且大小写数字混合、长度 ≥32 的 base64/hex 字符集。

**强键名**：`api_key` `access_token` `auth_token` `refresh_token` `secret_key` `client_secret` `private_key` —— 这些即使值不够"高熵"也报，因为键名本身就说明用途。

**裸密钥**：日志、代码块里常出现没有键名的 `ghp_xxx`、`AKIA...`、JWT，单独一轮扫描兜住。
