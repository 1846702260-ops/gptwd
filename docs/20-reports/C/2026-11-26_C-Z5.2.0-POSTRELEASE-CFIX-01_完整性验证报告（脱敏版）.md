## 3. 修复项与真实证据

### M1 · D-01 撤销墓碑根治（A 类）

**根因**（与 Z 缺陷单/复发补充单完全吻合）：
- `writeSeal`：`seal.lines` = 物理非空行数（含重复）；
- `loadTombstone`：校验 `seal.lines !== map.size + bad`，`map.size` 按 hash **去重**；
- 同一令牌经 logout_all / session_rotate / 改密重复撤销 → 重复行 → `TOMBSTONE_LINE_COUNT_MISMATCH` → tampered → `resolveEx` deny-all → 密码登录成功后新会话立即 401。

**修改前复现**（`/root/z52/evidence/repro_d01.mjs`，合成环境）：同一哈希撤销 3 次 → seal.lines=3 vs map.size=1 → tampered=true；**全新合法主人令牌被 deny-all 误伤**。Z 生产实证：195 物理行/194 唯一（hash 050b3d5b…×2）、184 行/186（hash 125171d7…×3）。

**修复**：
1. 口径统一：校验改为**物理行数**（与 writeSeal 一致）——历史合法重复记录 + 旧 seal **自动兼容、无需重签**（Z 已去重的生产数据 194 行直接通过）；
2. 幂等：`appendTombstone` 追加前跳过已存在哈希（并发窗口下仍可能重复 → 由口径兼容兜底）；
3. 并发：多进程交叉追加实测一致；崩溃中断（append 后 seal 未写）明确语义 = tampered → fail-closed → 受控重签；
4. fail-closed 全保留：SHA256 不符 / 缺 seal / 坏行 / 篡改（字节改、追加、删行）一律拒绝；
5. 新 CLI：`tombstone-verify`（只读，tampered → exit 9 + 处置指引）、`tombstone-reseal --accept`（自动备份 → 坏行拒绝 → 重签；**绝不清空墓碑、绝不删凭证**）。

**测试**：单元 6/6 + 真实启动 E2E 22/22（真实 config→loadConfig→startCompanion→真实 HTTP：登录→logout-all→4 轮轮换风暴→改密→重启→旧 Cookie 拒绝；历史重复行在场时新登录可用、被撤会话拒绝）。

### M2 · D-02 CLI 数据目录及恢复安全

- **修改前复现**：从 `packages/companion` 跑，旧 `resolveDataDir` 猜成 `packages/companion/packages/companion/data`（不存在）；Z 实证错目录时回退检测被静默跳过。
- **修复**：`resolveDataDirEx` 与服务端同语义 —— `--data-dir` > `ZY_DATA_DIR` > `--config`/`ZY_CONFIG` 的 `dataDir`（**相对路径以配置文件所在目录为准**）> 仓库默认（脚本位置推导，**与 cwd 无关**）。
