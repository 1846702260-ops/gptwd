### 2.3 为什么没有改成 Z5.2.3

拟发布版本是 Z5.2.3，但改版本号=宣告发布。G 明确「最终版本与部署须经 G 裁决及主人授权」。候选里保持 Z5.2.2，把 5.2.3 的两处改动（`version.ts` 一行 + `deploy-linux.sh` 的 BRANCH）写成待授权清单，授权后一条命令完成。

## 4. 实时通道验收

### 4.1 先说清基线有什么

生产 Z5.2.2 的"实时"只有两处：

1. **任务过程流 SSE** — `GET /api/ws/autonomy/tasks/:id/stream`，首帧 `hello` 带 trace 快照，之后订阅 `TaskStore.onEvent` 增量推送，15s 心跳，客户端断开即退订清定时器。
2. **桌宠 chat 伪流** — OpenAI 兼容 `stream:true`：先发 `role` 空 delta，再一次性发完整 `content`，然后 `[DONE]`。**没有 token 级增量**。

没有 WebSocket 服务端，没有跨设备消息分发，没有 `Last-Event-ID` 断线续传。这些是 E 候选的职责。

### 4.2 验了什么（真实服务，14/14）

启动方式：真实 `startCompanion` + 真实配置 + 真实账号登录（`POST /api/web/auth/login`）+ 真实 HTTP 会话，隔离数据目录与端口，不碰生产。

| 断言 | 结果 | 证据 |
| --- | --- | --- |
| 主人登录 | ✓ | 200 + session cookie |
| 生核状态 / 忆核接口 | ✓ | 均 200（合并未破启动） |
| 未认证订阅流 | ✓ | 401 |
| 伪造会话订阅流 | ✓ | 401（服务端签发才认） |

### 4.3 一个必须说清的边界

「不同主体不会收到不属于自己的实时事件」这条，我只能给出**两层**证据：

- 接口层：无身份/伪造身份进不来（401），不存在的资源 404，不泄露存在性以外信息
- 代码层：`owns(t)` 判定（`isOwnerActor || t.ownerId === actor || kind === 'practice'`）+ `store.onEvent` 里 `if (ev.taskId !== id) return` 双重过滤，且只转发白名单事件（`trace_delta` / `transition` / `step-*` 等）

**我没有伪造第二个登录主体来凑这条证据**——产品是单主人账号设计，建不出第二个真实主体；伪造出来的"隔离通过"证明不了任何事。这条要真正闭环，得等 E 的候选到位后，用两个真实设备/两个真实会话验（E 的报告应有对应场景）。

## 5. 测试脚本指向核查（G 第 7 条）

### 5.1 方法

遍历 `packages/*/test/**`、`packages/*/src/**`，搜：`work/wt-`、`work/zyagi`、`D:/WorkBuddy`、`/workspace/`、其他工作树绝对路径。

### 5.2 结果

**无测试从别的工作树导入代码。** 这条不是运气——上一轮我踩过：`c-m2-closedloop` 曾硬编码 `D:/.../work/wt-final/packages/companion` 作为 `ROOT`，后果是**在任何别的工作树里跑，导入的都是 wt-final 的代码**，于是"通过"与当前候选无关。当时是在跑影响范围时它对着未合入补丁的树报了绿才发现。这次逐条核查确认已无同类问题（该文件已改为 `import.meta.dirname` 相对定位）。

**发现并修掉 2 处绝对路径写盘**：

| 文件 | 原状 | 修法 |
| --- | --- | --- |
| `c-m2-closedloop.test.mjs` | `writeFileSync('D:/.../.workbuddy/tmp/m2-closedloop.txt')` | `C_EVIDENCE_DIR` 或 `os.tmpdir()`，写失败不判红 |
| `c-m3-ui-server.mjs` | `READY = 'D:/.../m3-ui-ready.json'` | `C_M3_READY_FILE` 或 `os.tmpdir()` |

这类缺陷的危险在于"看起来没事"：在本机跑一直通过，换机器或换工作树就 ENOENT；而 ENOENT 出现在收尾处，最容易被读成"通过但有噪音"。

### 5.3 我自己也犯过一次同类错

`c-z523-realtime.mjs` 第一版我用了 `/api/ws/tasks/...`，实际生核路由挂在 `/api/ws/autonomy/tasks/...`。结果"不存在的任务 404"这条**假通过**了——因为整个路由不存在也是 404。修了前缀后才有意义。教训：断言 404 时必须先证明 200 路径能通，否则 404 分不清"资源不存在"和"路由不存在"。这条已写进测试文件注释。
