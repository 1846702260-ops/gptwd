G1 身份安全：R 选型报告否决整体引入 Better Auth（双认证真源、体量大、Passkey 默认 UV 为 preferred 且 TOTP 无重放闸），确认组件化路径。K 的 Passkey 用 SimpleWebAuthn 14.1.0，MIT、精确锁定、生产 Node 满足。ownerId 实测九项全过：已落盘与配置冲突即拒绝、配置在身份库不存在即拒绝创建新主人、多 ownerKind 歧义拒绝、空配置拒绝、服务身份与字面量 owner 挡住，邮箱文本与请求体字段一律不采信。开关旁路风险重点排查后排除：状态损坏时认证服务仍装配且读接口抛错转五百，不会静默回退旧路径；关闭开关才走旧链路，访问口令层仍在，V2 登录可达。两处偏差为 B 类：scrypt 用 N 等于二的十五次方而非任务书默认二的十六次方，实测单次约九十三毫秒；TOTP 为自研 RFC6238 而非 R 推荐的 otplib，但跨进程重放闸实测正确。二者提交裁决，不擅改。

G2 真实链路：C 独立负例与 K 专项均过。密码正确未过第二步只发挑战不发会话；TOTP 同秒同码二次提交被拒；未知账号与错密码统一错误码且都跑一次哈希防枚举；主人会话缺第二因素时对全部主人资源返回四零三，普通用户进不了安全中心；会话换发撤销旧令牌，改密改邮箱与关 MFA 需近期重认证；伪造 Origin 被拒，请求需自定义头与 JSON；Passkey 的 RP ID 与来源由服务端白名单预设不从任意头推导，强制 UV，计数器兼容同步凭证零值并拒绝回退，默认关闭。离线恢复仅本机命令行、一次性高熵凭证撤销全部会话与凭证且 ownerId 不变。
