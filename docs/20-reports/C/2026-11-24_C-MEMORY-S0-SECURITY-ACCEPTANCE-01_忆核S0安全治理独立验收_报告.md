## 四、M2 S0-B 可信身份源

详见 04 号文件，此处给结论。

### 4.1 身份链梳理

`认证入口 → 会话/设备绑定 → 可信主体映射 → 记忆读写 → 工具授权`：

- **认证入口**：`/api/web/login`（访问口令，可选）→ `/api/web/session`（签发 `zy_web` 设备令牌）；`/api/pet/chat`（`pet.token`）；`/api/pet/service-chat`（`pet.serviceToken`）。
- **主体映射**：`WebSessions.issueIdentity()` 的 `userId = this.ownerId || 'web_' + random`；`resolveIdentity()` 为 `return this.ownerId || rec.userId`。
- **身份分层**：主人（`ownerJudge.isOwner`）/ 普通成员（`web_xxx` 且非 owner）/ 服务身份（`service:dsh`）/ guest（`pet:guest`）/ 未认证（无令牌）。

### 4.2 两种形态的真实实测

| 形态 | 实测结果 |
|---|---|
| **生产形态**（配置 `web.ownerId`） | 两个全新客户端各自 `GET /api/web/session`，返回的 `userId` **完全相同**，且等于配置的 `ownerId`。不存在第二个主体。 |
| **未配置形态**（`web.ownerId` 为空） | 两个全新客户端得到**两个不同的** `web_xxx`，且都不等于 `owner`。成员↔成员隔离可在真实链路上验证。 |

未配置形态下的真实 HTTP A/B（真实 Cookie、真实 `coreTurn`、真实账本）：A 的私密内容不出现在 B 的提示词；B 不出现在 A 的提示词；主人预置记录未出现在任何成员提示词中、也未被改写；重启后仍然隔离；B 访问 A 的会话返回 404。

### 4.3 判定

- **阻断性质**：架构性（单主人部署 + 无成员账户体系），**不是配置错误、不是测试环境缺陷、也不是 S0 的缺陷**。
- **S0-B 状态**：**BLOCKED**。不得把"所有设备等同主人"当成多用户隔离验收通过。
- **收窄后的边界**：成员↔成员隔离**已可验证且通过**；主人↔成员隔离在生产形态下**不可构造**（无法以主人身份登录测试一个成员）。
- **与 P0 的关系**：P0 的 U1（`legacyOwnerPolicy='deny'`）+ R3（`kind`/撤销）提供了"签发证据"的基础，但**不提供第二个主体**——它让"谁是主人"更严，不让"谁不是主人但仍是合法用户"出现。因此组合 P0 后 S0-B **仍然阻断**，只能后置到"引入成员账户体系"之后（见 06 号文件）。
