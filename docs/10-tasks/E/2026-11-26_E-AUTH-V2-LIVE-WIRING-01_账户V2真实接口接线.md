在已交付的 E-AUTH-V2-SECURITY-UI-01 V1.1 前端候选上完成 K 真实认证接口接线，不重做 UI。K 后端候选坐标（HEAD/Tree/Parent）与共同祖先基线以内部交付记录为准，公开版从略；K 候选未推受控仓库，必须从 K 正式交付批次取 bundle/patch/接口契约，核对三坐标、哈希与祖先关系。E 保持独立 worktree，不向受控分支写入。C 可独立核查 K 后端，接口缺陷由 C 协调 E 对齐，不重复施工。

## 工作内容

1. 以 K 实际 25 路由、四态（anonymous / incomplete / full / reauth_required）、错误码、Cookie/CSRF/Origin、challenge 生命周期为依据建立真实适配器；逐条验证实际响应，消除 mock 与真实 API 的差异。Mock 仅用于测试，不可作为生产回退或成功依据。缺接口准确报告并协同 C，不造安全旁路。
2. 真实登录页随服务端认证开关状态启用；关闭时保留旧路径与行为；V2 启用时不回退至旧认证。未完成 MFA 不展示或加载主人资源；错误、取消、过期、重试、退出、设备撤销及会话失效处理正确。密码管理器自动填充，邮箱、密码、动态码可粘贴；不用 localStorage/sessionStorage/日志缓存令牌、验证码、密钥、恢复码或 WebAuthn challenge；恢复码仅一次展示、离开清除。
3. 登录支持邮箱密码、服务端要求时动态码/备用码、Passkey（服务端开关与浏览器能力双门禁）；优先复用成熟 WebAuthn 浏览器组件，核查版本、许可证与选项编码兼容性；不伪造系统生物识别窗口。Passkey 未获真机验证保持生产关闭。无 SMTP 时如实显示离线恢复说明，不显示发送邮件成功；不添加公开注册或在线恢复旁路。
4. 安全中心固定「总览→左抽屉→账号→安全中心」，底部「总览/聊天/状态」不改；邮箱、密码、动态码绑定/确认/关闭、备用码、设备撤销、退出其他设备、登录活动、Passkey 注册/命名/撤销及近期重认证全部真实接线，主人 ID 只读且不作为权限证据，保留既有第三方入口。不改后端权限、桥、备份、桌宠与三主页面布局。
5. 隔离真实 K 服务与合成账号测试，至少覆盖密码、MFA 未完成拒绝、动态码/备用码、设备撤销、密码与邮箱修改、Passkey 软认证器正负流程、开关禁用、恢复说明、失败提示、手机视口及键盘/焦点/滚动。区分软件认证器、模拟视口与真机 iPhone Safari/PWA；真机留 Z 与主人执行，不能冒充已验。类型检查、生产构建、相关回归；不重复无关的全量后端测试。
