## 目标
用户已确认：邮箱+密码登录，可选 Authenticator、Passkey 免密登录，免费自托管，永久继承主人 ID。仅做实际可操作的登录和账号安全中心，保持现有界面风格及移动端结构。独立 worktree/分支，以受控候选基线为起点，核对真实源码和正式交付坐标；与 K-AUTH-V2-OWNER-CONTINUITY-01 共享只读接口契约，不共享写目录或改后端认证。R 选型未定时先做真实 UI 盘点和合成契约测试，K 接口确认后完成接线。

## 固定页面边界
底部三按钮保持「总览、聊天、状态」，不得改称更多、增加新主页面或调整既有导航。入口严格为「总览 → 左侧抽屉 → 账号 → 安全中心」。复用既有账号入口、抽屉滚动、页面组件、主题，禁止全站重做或桌宠开发。优先 iPhone PWA 和桌面 Web；注意安全区、软键盘、输入框闪动、返回导航及屏幕阅读器。

## 页面与真实行为
1. 登录页：邮箱、密码、显示/隐藏密码、记住登录、登录按钮、离线找回入口；正确 autocomplete=email/current-password，允许密码管理器、粘贴；统一错误，不透露账号存在性。不设公开注册链接。未配置 SMTP 不显示虚假的邮件发送/找回成功。
2. MFA：仅当服务端返回 challenge 时进入六位验证码页，支持粘贴、备用码入口（仍需密码阶段），过期返回登录；未完成 MFA 不能渲染或调用受保护功能，前端守卫不代替服务端。错误与网络中断可恢复；禁无限自动重试、禁模拟登录成功。
3. 安全中心：登录邮箱与密码修改、Authenticator 开关/绑定二维码/手工密钥/验证码确认、备用恢复码生成及重新生成（仅一次展示，不自动写缓存/日志/剪贴板）、登录设备列表/撤销/退出其他设备、近期登录活动。敏感操作按 K 返回的重新认证流程；未配置 SMTP 显示邮箱是登录名、未邮件验证，恢复使用受控离线方式。账号恢复说明清楚区分 2FA 备用码与独立忘密恢复凭证；无实际后端则显示未接通，不声称已完成。避免重复暴露二维码和密钥，离开页面清理临时状态；禁止 localStorage/sessionStorage/service worker 缓存密码、TOTP seed、恢复码、认证响应。浏览器安全 Cookie 由后端负责。
4. ID：可显示主人身份已绑定状态（服务端真实返回），不提供修改 ownerId 或任意账号绑定为主人的入口，不让用户手工输入身份锚点来授权。保留现有 QQ 绑定入口及状态，不重新设计渠道接入。

## Passkey 前端增量（正式功能）
- 登录页增加「使用通行密钥登录」按钮；可用时发起 K 的真实 WebAuthn options/verify 流程，支持 iPhone 系统密码/Face ID/Touch ID 界面（实际由设备决定），不绘制假系统认证窗口、不采集生物识别信息，不要求 Apple ID OAuth。原邮箱密码、Authenticator、备用码、离线恢复均保留。
- 总览→左侧抽屉→账号→安全中心内增加「通行密钥」：绑定新密钥、列表/名称/最近使用、撤销及确认，按 K 的近期重新认证契约；不可绕过已启用的 TOTP，不接受模型/客户端文本作为授权。没有真实后端不显示成功；服务端确认完成方可更新 UI。
- 使用成熟客户端库或浏览器标准 API，HTTPS/功能检测/服务端开关均满足才提供可用按钮；不支持、取消、超时、凭证不存在、已撤销、网络失败均提示并可返回密码登录，不自动无限重试，不强制跳转。浏览器调用过程不缓存 challenge、认证响应或秘密至持久存储/Service Worker，安全中心与认证响应不离线缓存。Passkey 私钥及生物识别数据由设备管理。
- 验证桌面浏览器及移动 Web 界面、虚拟认证器端到端、PWA 安装态/返回/系统弹窗取消与降级；iPhone Safari 和主屏幕 PWA 实际验收需 Z 协同主人执行，未取得真机证据标待验，不用模拟替代。既有三主页面不变。来源：https://developer.apple.com/passkeys/ 、https://better-auth.com/docs/plugins/passkey 。
