# E-FRONTEND-CAPABILITY-PREFLIGHT-01｜知遥能力可操作化预研

- 日期：2026-11-27（北京时间）
- 执行：E；决策：G；后续接收：C/K（经 G 裁决）
- 性质：能力盘点、既有接口复用研究、隔离交互原型；本轮不修改正式产品源码，不提交生产分支，不部署。
- 背景：Z5.2.0 已上线，生产归档坐标 `136aba5b`；C 已交付统一研发候选基线 `e4cd1b1`，完整坐标以 C 正式包独立核验为准。K 正在接续 S3 治理闭环，C 正式人格验收接续中。人格候选与在途 S3 接口不得当作已经上线的能力。

## 1. 目标

让主人未来能在手机 Web/PWA 中找到、理解、使用和管理已具备的能力，减少依赖报告或命令行。优先复用现有前端组件、接口、权限与交互机制，不新增第二套 UI 运行时、记忆系统、工具网关或审批系统。E1 已有成果先盘点，不重复造轮子。

## 2. M0：建立真实能力—界面映射

从 C 侧统一基线的正式交付获取只读源码/独立克隆，核实 HEAD/Tree，不能获取则报告阻塞，不从过期候选猜测。盘点记忆查询/来源/纠错/归档、人格版本与身份资产、成长记录、工具/插件/MCP/技能、工作任务与状态等已有功能。逐项记录源码路径与真实路由/接口、认证与授权、输入输出、前端入口、状态展示及缺口。

分类：①已上线且可操作；②已有接口但无入口或难发现；③只有候选/未完成；④规划/模拟。不得把不存在的接口写成可用。区别正式人格 V1.0 与生产 P1A；S3 待确认出口与摘要保真以 K/C 最终契约为准。不得访问生产私有记忆或未经授权的数据。

## 3. M1：手机 PWA 信息架构与操作方案

遵循现有三主页面（总览、聊天、更多）与总览左侧可滚动抽屉结构，保留近期已上线的「账号」「积分」等入口，不擅自改变导航主框架。评估已有的路由、页面、状态组件、弹层、权限提示与错误处理；优先提出少量高价值、最少操作步骤的入口。

至少明确三类优先候选：
- 记忆：查看已有记忆及来源、纠错状态；真实删除/确认等操作必须复用现有主人授权机制，未完成接口只做占位说明。
- 人格与成长：查看当前实际加载版本、正式候选区别、身份资产引用、成长记录（若确有来源）；不把人格原件或图像上传第三方，不开放未获授权的人格编辑。
- 工作与生态：现有工具/技能/插件的能力发现、执行状态、结果与错误；已有入口不重复建设，不自动执行敏感操作。

给出优先级、用户操作路径、权限边界、空/加载/失败/未实现状态、接口依赖与验收标准。沿用现有样式，考虑 iPhone 窄屏、触控区域、弹层 Portal、键盘、内部滚动、断网与登录失效；不做桌宠、3D/Live2D，不扩张 QQ 接入。

## 4. M2：隔离交互原型

选择最有价值的 1–2 条路径，基于现有组件规范做低成本可点击原型或隔离演示。允许使用合成 mock 数据，但所有模拟接口、按钮、结果显著标明，不代表生产可用。优先复用已有前端组件；不改正式源码，不接真实生产 API，不使用真实主人信息，不新增收费服务。可在单独目录/分支保留原型，交付可复现启动说明、截图与流程。

验证至少覆盖 320/390px 视口、加载/空/失败状态、权限不足及未完成接口提示。浏览器模拟与手机真机必须明确区分。若源码无法取得，只能基于有证据的报告提供部分方案并声明阻塞，不能宣称完成实际接口映射。

## 5. M3：后续实施拆分
