## 1. 本轮要达到的用户体验

在给定可靠、已授权的历史对话或结构化记忆时，陈知遥应当：

1. **能接住自然语言的回忆指代**，例如“昨天我跟你说的那个迁移”；即使本句没有精确关键词，也会尝试关联最近主题、时间和当前对话，能拿出有来源的正确事实。若有多个候选或证据不足，应先澄清，不能随便选一个。

2. **能真正记住主人明确的纠正**，例如“我之前说错了，不是凌晨两点，是三点半”；在隔离测试中，重新开会话、重启进程后仍优先使用更正事实，并能追溯旧记录已被纠正，而不是仅在同一上下文口头答应。

3. **不会将推测包装成两人共同经历**。回答“我们上次看流星时你说过什么”时，若只有“讨论过流星”的证据，没有地点、天气、时间或原话，就必须说清知道什么、不知道什么；不能补出一段仿真的往事。

4. **对反讽与情绪有上下文判断**。例如主人刚说某个操作失败，接着说“你可真行”，不能机械地当作夸奖。语境不足时保持温和、谨慎的理解，不强行诊断情绪。

5. **自我能力表述与真实能力一致、可复验**。不会把空白能力清单当成“完全没有能力”，也不会凭模型猜测声称具备未接通的工具；相关脚本应能按说明复跑。

> “修复完成”必须同时有 **代码路径证据 + 可复现自动测试 + 真实模型对话验证**；只改提示词、只改测试断言或展示一条漂亮回答，都不构成完成。

## 3. 必须完成的技术修复（一次性完成，禁止拆为多轮空转）

### A. 长句语义回忆、跨轮指代与时间线索（最高优先级）

**问题现象：** 直接提“迁移”可以关联记忆，但“昨天我跟你提过的那个迁移”可能检索失败。这说明用户自然问法与检索输入/上下文构造之间存在断层；具体根因需要 K 用日志、测试和代码定位，不能先假定是某个模型、BM25 或向量服务的错。

**实施要求：**

1. 保持 `memv2` 事实与原始对话来源不变，在现有检索接口上实现**轻量查询理解/检索增强**：识别指代词（“那个/上次/前天/之前说的”）、当前对话主题、时间范围和可能的实体；多策略查询应有数量上限，避免每轮额外多次大模型调用。

2. 同时利用**关键词命中、上下文主题、时间关联、来源可信度、实体一致性**；只有仓库已有稳定的语义检索能力时才调用它，不能为修一个 P1A 问题新上复杂向量库/图数据库或远端服务。

3. 检索结果要经同一身份/会话授权过滤；严禁跨主人、访客、群聊、工作档与私人会话混用。已有被撤销/遗忘/纠正的旧事实不能作为当前结论直接返回。

4. 对多个时间相近但主题不同的候选，必须有可解释的排序或澄清策略，不能只因新就取最新，不能把多条互斥记忆合成假事实。

5. 结果注入模型上下文时，保留必要的**事实/时间/来源/确定性**，避免只塞一段无来源摘要。无可核验记忆时显式表现“不确定、请提示”，而不是伪造“我记得”。

6. 保留原简短关键词检索的有效性，不让复杂问句优化导致普通检索整体退化；设置查询数量、上下文预算、超时和降级策略，不能因记忆系统异常而阻断普通聊天。

**完成标志：** 用虚构跨天历史构造同一事件的关键词、时间指代、长句、不同事件混淆和缺失证据场景；能够说明为什么命中或拒答，并在跨会话真实模型测试中得到稳定的事实性回答。

### B. 主人明确纠正的真实持久化与来源追溯（最高优先级）

**问题现象：** 模型接受“凌晨 2 点 → 3 点半”的口头更正，但新时间不进入长期记忆；下一次又返回错误时间。

**实施要求：**

1. 将“主人明确纠错”的有效会话事件引导至已有 `memv2` 纠正入口，正确定位原事实的 **ID/事实主体/作用域/事件时间**；没有可唯一定位的旧事实时，先询问或形成**待确认纠正**，不得任意批量覆盖同主题记录。

2. 使用现有纠错生命周期（如已有的 `correct → superseded`）记录**旧值、新值、纠正者、时间、来源证据、有效性/状态**。原始经历/证据仍可追溯，当前检索优先使用生效新值。

3. 严格区分“主人明确纠正事实”与玩笑、假设、模型自发推断、未经核实的第三方陈述。不得让模型自行改写主人身份、私人关系、授权与其他高敏感事实。

4. 纠错操作完成前不可向主人宣称“已经永久记住”；落盘失败、冲突或只写内存时必须报告真实结果，并保持数据不被半写破坏。

5. 覆盖**重启、跨会话、重复提交、并发冲突、存储失败与旧事实被检索到**的边界：同一更正重放应幂等，不能产生无穷多互斥记录；先前已被更正的值不可以从摘要/旧缓存“复活”。

6. 如已有“记忆查看/纠正记录”接口，则确保最新值与历史沿革一致；本轮不建设新的大型 UI，必要时以现有只读调试输出证实。

7. 遵守现有遗忘、删除、主人权限和隐私隔离规则，不借纠错路径恢复已经删除的内容。

**完成标志：** 用虚构时间、地点、项目名称至少三类事实验证“记下—纠错—跨会话/重启后召回—可追溯旧值”；同时证明普通未经授权语句不能改写事实。

### C. 共同经历、情节补写与来源诚实性

**问题现象：** 回忆过往时，模型把不存在的流星事件细节说成确实发生过；这会让“长期伙伴”的体验失真。

**实施要求：**

1. 在人格/回忆编排中明确区分**已记录事实、基于证据的合理推断、创作/模拟内容**，并沿用既有 self-model / 记忆来源标记，不得建立第二份“共同经历表”。

2. 当用户询问共同经历的具体地点、时间、原话或天气，而可用来源没有相关细节时，应清楚承认“这部分我无法确认”；可以自然地请主人补充，但不能把猜测写回为 `stated` 或高置信记忆。

3. 虚构故事与角色扮演可在明确创作语境中发生，但必须避免被当成真实经历保存；区分“我们来编一个流星故事”与“你记得我们上次看流星在哪里吗”。

4. 对模型输出做最小必要的事实来源约束/后验校验，优先通过上下文与生成策略解决，避免全系统引入昂贵的独立审稿模型或误杀自然交流。

**完成标志：** 对“有证据”“仅有主题无细节”“完全无记录”“用户明确要求创作”四种情况分别给出符合来源的答复，且不污染持久记忆。

### D. 反讽、语境与情绪表达的定向改善

**问题现象：** 发生失误后主人说“你可真行”，模型可能按字面夸奖理解。

**实施要求：**

1. 将**前文事件、语气与事实后果**作为理解输入：系统刚失败时，优先考虑抱怨/反讽；事情成功时则可能真的是夸奖。

2. 对模糊语句保持适当不确定性，不允许一条固定关键词规则把所有“你可真行”都解释为讽刺。

3. 纠错回应要具体承认已发生的问题、说明能否修正；不做夸张道歉、情绪诊断或人类身份伪装。

4. 与原有的人格 V1.0、情绪维度和表达风格保持协调；只做必要的提示、上下文或轻量规则调整，避免重新设计人格卡。

**完成标志：** 对同一句话在成功/失败/上下文缺失三类情景中能给出合理区分，并通过真实模型抽样，结果有逐例证据而非单一主观分数。

### E. 自我能力清单与复跑脚本的两个小缺陷

**E1 自我能力：** 找到造成 self-model 能力清单为空的实际路径。若确有能力信息，按现有注册/授权源如实呈现；若没有可验证的清单，提供诚实的“当前无法确认全部已启用能力”降级文案，而不是补写虚构工具。验证在无工具、有工具但未授权、工具已授权三类情形下不误报。不要把本项变成全量自我模型重构。

**E2 复跑脚本：** 确认 C 指出的相对路径“少一层”的脚本/文档位置，修正实际路径或以脚本自身目录作为稳定基准。要求从项目规范工作目录及任意临时工作目录分别复跑成功；不得依赖机器私有绝对路径、root 特权或临时文件残留。只修改影响本轮可复现性的必要脚本。

## 5. 预期实现细节与工程质量要求

### 5.1 数据与检索契约

- 给检索结果提供最小但充分的结构：`记忆ID / 来源类别 / 所属身份与会话范围 / 事实或事件时间 / 状态(有效、已纠正、已遗忘) / 已知内容 / 不确定性`。这些是**语义契约**，不要为了字段名字强制新建数据库。

- 对时间表述采取有依据的解析：自然语言“昨天”需以会话当地时间和真实消息时间为基准；无法确定时不臆定具体日期。

- 长句增强必须有限流、超时和回退到既有检索策略；记录可匿名化的命中类型、耗时和截断情况以辅助定向排错。

- `memv2` 为唯一可持久修改的事实来源；其余缓存、索引、上下文副本必须能随更正而失效/刷新，不能单独成为可见真源。

### 5.2 对模型指令与行为的约束

- 让模型有足够证据回答，而非靠“你要记住主人说过的事”这样的单句泛化提示。

- 采用**证据层级**：确定的来源事实优先；推测必须标注；缺资料时承认不知道；不能为了维持亲近感声称拥有不存在的回忆。

- 情感表达应自然、简洁，正事保持理性；不应过度拟人化到虚假现实身份。

- 同一条过去经历不得从创作输出自动变成真实长期记忆。

### 5.3 代码与测试纪律
