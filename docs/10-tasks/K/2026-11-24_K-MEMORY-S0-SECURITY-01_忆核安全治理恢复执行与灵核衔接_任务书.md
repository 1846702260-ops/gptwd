## 3. S0 原范围：忆核安全隔离与授权边界

以下是已记录的原 S0 范围摘要；以实际取得的原任务书为详细实施依据。不得借此扩大到全面安全重构或新增无关门禁。

### S0-1：`loadLessons` 等经验读取隔离

- 核对经验、教训读取实际调用链、所有者及作用域来源；不能只看参数名称或测试模拟。
- 默认按可信身份与作用域隔离。明确授权共享的内容按既有规则处理；未经授权不得把其他人的私有经验或私聊内容注入当前会话或工作档。
- 无可信身份、scope 缺失或越权时采用拒绝或不注入私有数据的安全行为，保留业务合理降级，不通过过滤输出词表代替读取边界。
- 用合成多用户样本检查正向授权、拒绝、主人不同会话/工作档、旧路径兼容；若已有可靠覆盖，复用并只补未覆盖路径。

### S0-2：按用户归档与恢复隔离

- 核对归档对象、用户标识、源记录、落点与恢复边界；归档和恢复不能跨用户串读、串写、误覆盖。
- 原始经历保留来源证据，结构化记忆唯一真源仍为 `memv2`；不创建第二套事实库，不静默清理旧记录，不删除真实用户数据。
- 用隔离目录与合成数据验证两用户分别归档、恢复、重新加载，异常身份/空身份不误归档、失败不虚报成功；保持先前已验收的备份与纠错能力。
- 如历史数据存在不明归属，报告范围及安全隔离建议，不自行迁移或删除生产历史数据。

### S0-3：DSH 最小 scope 与旧入口旁路治理

- 核对 DSH 现有接入、授权与 scope 传递，旧接口/兼容路径是否绕过同一访问边界；只处理原任务所指向的相关路径。
- 权限以服务端可信授权为准，不能依赖模型输出或客户端声明自行提升；无 scope 时不默认授予主人权限。验证正常授权仍可完成原业务、拒绝越权与旧旁路。
- 已通过验收的身份安全模块不因本任务重写；桌宠当前不开发、不修复、不验收，已授权交付的既有 P0 桌宠绑定令牌安全成果不回退。如原路径实际涉及已暂停桌宠功能或生产授权变化，隔离相关冲突点，提交协调，不扩范围。

## 4. 忆核—灵核衔接：轻量设计与可测证据（本轮只读或合成探针）

这部分只补已有 M0 方案与心核最新修复之间的衔接差异，不另开大型研究、重构或 S1/S2 实施任务。

### 4.1 盘点现有链路

沿现有真实对话入口，梳理「用户请求 → 身份/会话授权 → 查询理解 → 记忆召回与排序 → 上下文预算/注入 → 模型推理 → 纠错或经验写入」的实际路径。标注模块、输入输出、权限、持久化、失败回退及当前是否真正接通。尤其核实：

- `memv2`、现有评分与融合检索、`tokenCalibration`、`TokenBudget`、`rollup` 是否处于真实入口调用链；区分已实现、已接线、已验证、未接线。
- 本轮心核已通过的长句查询、时间线索、追问回退、事实纠正、出处约束和记忆去重由哪些现有能力支撑；是否需要保留既有 API 或约束。
- 稳定身份、明确主人偏好、事实经历、关系、任务进展与经验教训在逻辑层的分类及授权边界；不因分类创建五套物理数据库。
- 灵核是否可取得足够的当前目标、前文指代、可用工具/授权及可信记忆；缺少信息时如何标记不确定，避免把推断当成主人明确决策。

### 4.2 给出后续 S1/S2 衔接建议，不提前开发

- S1：优先统一已有评分、检索入口、召回依据和上下文消费路径；说明 `tokenCalibration` / `TokenBudget` / `rollup` 既有能力需在何处接线、是否有重复逻辑或状态断点。不要直接引入 Hindsight/Graphiti 数据库、Letta/LangGraph 框架，也不要并行维护新旧双真源。
- S2：上下文预算、水位、压缩、结构化摘要、归档和恢复闭环。确保压缩摘要不替代原始证据，不无依据丢失稳定偏好或重要事实；说明超预算降级和可测量指标。
- S3：治理增强；S4：旧路径退役及回归评测固化；S5 模型迁移、S6 多模态长期记忆仍为后续方向，不进入当前实施范围。
- 灵核后续目标：识别显式要求、合理推断隐含意图、区分一次性要求与长期偏好、识别不确定性、评估是否需要询问、在授权边界内给出低打扰决策。本轮只定义验证场景及依赖关系，不新建通用意图分类器或多 Agent 架构。

建议为 S1/S2 提供小规模、可复现的合成基线样例（以已有测试复用为先），例如：

| 场景 | 目标 |
|---|---|
| 主人明确说「以后文件名加中文」 | 识别长期偏好，而不是只改一次；不擅自重命名历史文件。 |
| 主人只说「看 C」且上文是研发报告 | 用任务上下文确定目标，读取对应报告，不反复问已知内容。 |
| 明确事实被主人更正 | 召回新事实，旧值不重新进入 active 事实池，保留演化来源。 |
| 模糊追问与新话题交错 | 相关时用前文，不相关时不硬凑旧事。 |
| 过去经历缺乏证据 | 明确不知道或无法确认，不补写共同经历。 |
| 一次性请求和长期习惯冲突 | 优先当前明确授权；不把一次性例外无依据永久化。 |
| 其他用户尝试读取/改写主人偏好 | 拒绝或安全降级，不泄露私有内容。 |
| 上下文预算不足 | 优先保留身份、权限、当前目标与关键来源；记录降级，不虚报完整回忆。 |

这些是设计与评测建议，不是声称当前所有场景均已通过；S0 验收以相关安全边界为主，不用未来灵核目标倒逼 S0 无限扩大。
