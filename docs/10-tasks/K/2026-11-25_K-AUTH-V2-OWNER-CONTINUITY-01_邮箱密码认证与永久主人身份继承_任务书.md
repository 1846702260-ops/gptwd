## M0 盘点与契约
核对实际 ownerId、账户与身份账本、ownerJudge、登录/改密/撤销、Web/QQ/代理/本地入口、记忆 scope/subject、数据备份及恢复；记录路径行号和现有缺陷。唯一稳定 ownerId 继承现有真实身份，不将所有用户折叠为主人、不创建新主人、不凭邮箱文本匹配。认证账户 ID 与永久主人 ID 分离，使用经验证的唯一绑定；如现有映射歧义、碰撞、空值或身份不一致，停止迁移并报 G，不能静默猜测。普通用户既有身份与权限不变。账号 ID 非秘密也非凭证，模型、提示词、客户端请求体不能授予或修改主人权。禁止第二套互相绕过的认证真源。

## M1 登录、密码与会话
使用 G 确认的成熟框架或组件，固定依赖/许可。邮箱登录（规范化及唯一性规则明确，保留原始展示，避免供应商特定别名猜测）；默认关闭公开注册及任何绕过注册 API，邮箱未配置 SMTP 时仅为账号名、不得声称邮件所有权已验证。密码优先 Argon2id 或现有成熟 scrypt，随机盐、合理资源参数（在隔离 Linux 实测）、支持密码管理器与长密码，不保存明文；默认至少 15 字符，可接受至少 64 字符，禁静默截断，限速与统一错误避免账户枚举。使用可信 HTTPS/HttpOnly/Secure/SameSite 会话 Cookie 或经审计的现有等价方案，CSRF/Origin/代理信任校验，登录后换 session，服务端撤销，有限有效期。记住登录仅延长受控会话，不默认开启跨新设备免 TOTP；不新增指纹跟踪。设备列表、退出其他设备、登录活动最小化记录（不记录凭证）。改密/解绑第二因素及邮箱修改需近期完整重新认证（密码+已启用的第二因素，或有效 UV Passkey）；恢复按 M3 独立受控流程，并按风险撤销其他会话。邮箱变更保持 ID 不变，无 SMTP 不冒称验证。

## M2 可选 Authenticator
标准 RFC 6238 TOTP（Google/Microsoft/2FAS 等兼容，6 位/30 秒，合理窄时间窗口），默认关闭；先生成密钥与绑定二维码，实际验证成功后原子启用，失败不改变原状态。密钥服务端加密，独立受限加密密钥可受控备份恢复，禁止日志、遥测、明文配置、公开报告或前端持久化泄漏；绑定 QR 仅在受认证临时页面展示。启用后密码正确只产生短期受限 challenge，不能访问主人 API/WebSocket/聊天/工具/记忆；完成 TOTP 才签正式会话。验证码限速、有效期、跨进程防重放；恢复码高熵、只展示一次、散列存储、单次原子消耗，更新废止旧码。使用备用码仍需要密码；禁用/重置 2FA 要重新认证，不能用旧访问口令绕过。已有设备会话启用 2FA 后撤销或强制重新验证。无短信、无云依赖。

## M3 离线恢复与迁移
无 SMTP 是首版默认。忘记密码采用独立高熵离线账户恢复凭证（与 TOTP 备用码不同）及受控本机恢复流程；最小可实现为既有受信任本机管理员 CLI + 离线恢复凭证校验，不做公开万能重置接口。凭证一次性、散列存储、重置后撤销所有旧会话和恢复材料，保留同一 ownerId，重新绑定 TOTP 的流程明确。首次绑定/迁移只能由已验证旧主人加受控本机操作或等价已审计流程发起，不能由首个访问者抢占；真实邮箱密码由主人本人在正式批准后的安全界面设置，不索取或代设真实秘密。迁移幂等、事务/故障恢复、前后 ID 与记忆关联对账；旧密码/访问口令/免密/代理头/旧 API 不得继续作为主人登录旁路。若仍保留普通访问口令，仅维持既有明确低权限契约；QQ 仅沿用已验证渠道身份及授权范围，不授予管理安全中心权限，不强制迁官方 API。无新多成员系统。认证状态、映射、撤销墓碑、加密密钥按受限恢复契约纳入备份，恢复旧备份不复活旧会话/已撤销凭证；无法证明时禁止发布，给出可执行安全回退，不回退到旧口令复活状态。

## M4 对 E 的接口交付
在现有 API/会话约定下给出具体路由、请求/响应 schema、状态机、错误码、CSRF 规则（不强制另建一套 API）。至少覆盖登录、Passkey 注册/登录 options 与 verify、列表/命名/撤销、TOTP challenge、启用/关闭/重生成恢复码、邮箱密码修改、设备/活动/退出、离线恢复说明。明确未认证/仅通过密码/完整认证/需要重新认证四态。E 只用合成契约，无真实秘密。安全中心入口固定总览左抽屉→账号→安全中心，底部总览/聊天/状态不变。Passkey 为本轮正式功能；暂不做邮箱发送、社交登录、自研人脸/指纹。不得以未接通后端的模拟成功作为交付。

## M5 Passkey（通行密钥）免密登录
1. 复用 R 验证且 G 批准的成熟 WebAuthn 实现；优先稳定版 Better Auth Passkey 插件或 SimpleWebAuthn，不自写密码学。若选 Better Auth，2026-11-03 公告 GHSA-gv75-j3v8-3crm 的稳定 1.7 线修复版本为 1.7.16，须选已修复且经最新公告核查的稳定版本，相关包统一版本，并实际验证修复配置。来源：https://better-auth.com/blog/security-release-2026-11-03 、https://better-auth.com/docs/plugins/passkey 、https://www.w3.org/TR/webauthn-3/ 。
2. 固定经核实的 HTTPS origin 与 RP ID，严格校验代理及允许来源；不得信任客户端提交的 ownerId、email、origin 或 Host 决定授权。注册仅在已认证账户近期完整重新认证后进行（已启用 TOTP 的密码路线须验证 TOTP），拒绝未认证/仅密码阶段绑定。challenge 随机、短期、单次、按操作和会话/账户绑定、原子消耗。服务端验证 challenge、origin、RP ID hash、签名、UP/UV、凭证归属、userHandle；注册及登录均要求 userVerification=required，不接受仅 UP 或客户端声明。凭证 ID 唯一，不允许重绑定到其他账户。采用可发现凭证，提供直接免密入口；允许标准同步 Passkey，按库/规范处理计数器及备份状态，不因同步计数器为零盲目拒绝或忽略真实异常。
3. 认证策略：有效 Passkey 加设备本地用户验证作为独立完整登录方式，不额外强制密码或 TOTP；密码登录若开启 TOTP 则仍强制 TOTP。两条路线共用同一账户、永久 ownerId、权限与会话撤销机制；不创建新用户、不通过凭证 ID 公开查询身份。Passkey 登录不允许未注册凭证自动建号。敏感操作（新增/撤销凭证、改密、改邮箱、重置 MFA、恢复材料）要求近期完整重新认证（密码+已启用 TOTP，或已绑定且有效的 UV Passkey）；离线恢复保持原 V1.0 独立受控流程，不把普通设备解锁视为账户恢复。不得因新增凭证降低密码路线保护。
4. 保存 credential ID、公钥、稳定不透明 userHandle、关联账户、必要计数器/备份状态、名称与使用时间；不采集或存储人脸、指纹、设备私钥。安全中心可绑定多个凭证、列表、命名、撤销；撤销立即拒绝其后续登录，并撤销由该凭证签发的现存会话（若无法可靠归因则撤销全部其他会话）。离线恢复撤销旧凭证和会话，防旧备份复活；保留至少一种独立可用恢复路径。域名/RP ID 变化可能需要重新注册，禁止静默迁移密钥或宣称跨任意域名可用。旧主人映射与记忆关系保持不变。
5. C 验收新增正负对照：注册与登录、重复/过期 challenge、错误 origin/RP ID、UV 缺失、篡改签名/账户绑定、他人凭证、未完成 TOTP 注册、撤销及恢复后旧凭证拒绝、同步凭证计数器、密码路线不降级、重启/恢复 ID 不变。用隔离 HTTPS 环境及虚拟认证器验证，不冒称 iPhone 真机通过；Z 后续经授权验证生产域名和 iPhone Safari/PWA。真机/域名未通过前保持 Passkey 默认不可用或受控开关，不影响已验证密码+TOTP 与离线恢复；不得据此开放不安全旁路。
