## 3. 已知问题（来自 C S1 报告，须源码确认）

1. `contextAssembler.assembleContext()` 为 compose 主链唯一组装入口；`runtime.js#composeTurn` 调用。
2. `contextConfig.budgetTokens` 默认 320、范围 80–4000；实际裁剪按字符近似，`tokenCalibration` 的 EWMA 模型分桶估算只用于统计展示，未参与裁剪。
3. `lifecycle/budget.js` 的 `TokenBudget` 由 `LifecycleRuntime.planBudget()` 使用，但主链无调用点；有双预算语义。
4. `WorkingMemory.rollup()` 未接真实 turn 链；实际 `WorkingSessionStore` 存在 `MAX_TURNS=30` 硬截断，archive 接点未形成闭环。不能把报告中的“零调用”直接等同于所有运行时场景均未使用，先核实。
5. 融合候选 `k=12` 固定上限可能令预算选择在较大记忆库中失效；需按实际规模测量，不简单无限增大。
6. B-1 他人信息可能以“关于用户的记忆”呈现，S2 做最小主体归属与摘要、归档、恢复隔离；B-2 否定整句误读及复杂事实切分留 S3，S2 不恶化。C-1 口语省略和显式“以前”查找不足不等同于压缩丢失；S2 必须保证被压缩的已知证据可按授权 ID / 时间 / 会话恢复，并在有足够线索时接回原 S1 检索，不全面扩张语义检索词典。S0-B 完整主人/成员并存仍 BLOCKED，不搭新多用户体系。

## 5. 实施任务（一次交付，分门禁验证）

- 给出唯一预算决策者、全请求与记忆子预算之间的关系、压缩水位和写入边界。复用已有 `TokenBudget`/`tokenCalibration`/`assembleContext`/`WorkingSessionStore`/`rollup` 能力中可用部分；明确哪些作为适配层，哪些暂留回退，不并行创建第三套工作记忆。
- 冻结基线同样本结果、源码差异和验收判据。若与报告冲突，先按证据更新设计，保留任务目标及安全边界。

### M1 唯一预算与真实 Token 口径

- 以模型上下文上限为外层容量约束，预留输出、系统/人格、权限、工具 schema、消息封装、当前用户请求和必要安全余量。记忆/历史/摘要/工具结果共享同一全请求预算账本，各分区不得独立满额后再叠加。不能只检查记忆块却让最终请求超限。
- 实际可用 tokenizer/官方计数接口优先；否则使用现有校准估算，按模型与能力/版本分桶、保守余量、明确估算标识。可获得 usage 时校准并记误差、样本数量及冷启动；不得把字符或估算叫作精确 Token。模型上限、输出限额以可信配置/官方能力和接口探测为准；未知取安全保守值并说明，不硬编模型上限。避免为了计数额外调用模型。
- 在统一组装决策中真正使用计数/估算；最终序列化请求复核总量（包括工具消息结构）。不可裁剪的必要内容单独超限时明确拒绝/安全降级，保留原始输入，不静默截断关键权限、人格、当前请求或工具调用的配对结构。
- 保持 S1 检索评分、scope、授权和纠错语义；候选池按预算、相关性和规模有界调整 `k`，给出默认、上下界及资源上限，不能用全量注入换召回率。解释是否需要旧 320 Token 兼容配置与迁移策略，不强改生产参数。
- 诊断至少包含预算源/模型、硬上限、保留输出/安全余量、各区使用、候选/拒绝/裁剪原因、最终估算、实际 usage（若有）、估算误差与超预算/降级原因；不记原文、完整 prompt、凭据。

### M2 水位与滚动压缩

- 设计可配置软/硬水位、目标水位及回滞/冷却；以容量比例和实测数据选默认值（可先试 70%/85%/60%，这仅为实验起点，不是强制上线值）。压缩不因每轮浮动反复触发，正常短会话不新增必经模型请求。
- 压缩优先处理旧工具大输出、冗余/低相关内容和较早历史；保留近期完整消息、主人明确纠错、已确认事实、时序、事实/假设/他人主体区别、待办/目标及权限边界。摘要为派生视图，记录来源 ID/区间、时间、版本、主体/scope、生成方式；不生成未经来源支持的新事实，不替代 memv2 权威记录。
- 如需模型摘要，只在水位触发的有界路径调用，限制次数/耗时/Token/重试；输出必须验证结构与来源，不将摘要中的指令当系统指令。先实现安全本地降级，模型超时、拒绝、无效结果或并发冲突时不损原文、不标已压缩、不阻塞正常请求到无限等待；必要时使用保守窗口并明确上下文不足。
- 解决 `MAX_TURNS=30` 硬截断导致的丢失风险：超窗前必须确认原文/证据已持久化；已有原始经历真源可直接引用，避免重复写入完整副本。保留必要的并发、会话顺序与幂等保护。不得清空历史或强制全库重算。

### M3 归档、恢复与一致性闭环

- 明确“写入原始经历→生成/校验派生摘要与归档索引→原子发布→退出热窗口→授权检索→恢复必要片段→再次纳入预算”的状态机，原始证据仍存、memv2 继续唯一结构化长期记忆真源。归档是已有经历的可定位持久化/索引，不是另一套长期记忆系统。
- 复用现有 archive 字段、归档路径和主体分片；采用安全的原子提交、版本/CAS 或等价并发机制，失败不删除原文、不推进已完成水位、不重复归档或重复注入。对中断、损坏、重启、重复请求、并发 turn、旧格式迁移、缺少 ID 做可恢复处理。
- 恢复必须在读取前执行可信主体、scope、工作档、时间与授权过滤；恢复后经过同一 S1 准入、去重、预算与证据有效性判断。不得以摘要绕过 S0/S1 隔离；来源被纠正、撤销、删除或权限变化时，失效派生视图不得复活。B-1 最小主体标识（本人/他人/未知，未知不冒充本人）贯穿上下文、摘要、索引与恢复；不开展 S3 全库语义重写。
- 实现有界按需恢复（来源 ID/时间/会话等，兼容已有 S1 检索），验证被压缩的有效历史可找到、恢复不全量塞回上下文。明确“旧经历没有可用线索”“档案损坏/不可访问”“当前权限不足”的安全表现，不能编造。
- 保持兼容迁移与回退：旧数据可读，新增派生状态可重建；配置回退不可关闭必要身份隔离或丢失已经持久化的证据。legacy 仅安全回退，S4 才处理完整退役。

### M4 可复现评测与真实双模型验证

1. 冻结同数据、同请求、同配置对照，覆盖短/中/长会话（至少跨旧 30 轮边界，建议 60–120 轮合成轨迹）、长中文与混合文本、巨大工具结果、稀疏/较大记忆库、反复水位触发。主链测试捕获真实组装请求，不用独立演示脚本代替接入。
2. 验证阈值附近、硬上限、必要内容超限、估算偏差、冷启动、模型切换、并发、摘要失败、断电式中断/重启、归档缺片/损坏、重复恢复、历史纠错、他人主体、跨用户/工作档/群聊、诱导指令、已删除/撤销来源不可复活。正反例各有预期，所有授权及数据完整性门禁必须通过；测试使用合成资料与隔离存储，严禁使用真实私人记忆。
3. 指标：每轮输入估算及可取实际 Token、峰值、平均/P95 组装时延、压缩次数及额外调用量、摘要前后字节/Token、关键事实/待办/纠错保留率、授权恢复成功率、错误归属/泄漏/编造/重复注入数、归档覆盖/原文完整性。报告同口径基线与候选；不能把 Token 节省等同智能提升，不以固定压缩率替代语义正确。硬门禁：隔离与来源一致性零新增失败；已持久化原文不得因 S2 丢失；在已确认容量边界且计数可用时不得发送已知超限请求；计数不可精确时必须保守预留并如实记录。
4. **主人指定真实模型：`hy4flash` 与 `DeepSeek-V4.1-Flash`。** 先核实可访问接口、实际 model ID 对应、容量/usage 能力与授权；未经确认不可将别名或其他模型算作上述模型。两模型同题、同测试口径；各至少 12 个有代表性的场景（含长会话压缩后召回、纠错、历史恢复、他人归属、工作档隔离、无答案不编造、模型切换），优先重用冻结轨迹构造临界窗口，避免无必要的全量真实模型调用。以真实主链生成报文并通过真实接口，区分报文层和模型层，记录实际返回模型标识（若提供）、请求数/耗时、输入输出 Token（若返回）、失败及降级。初始预算每模型 12 个主验证请求，额外摘要与必要准备/重试单独登记和设上限；如需明显扩大调用成本先报告。单模型或凭证不可用标 BLOCKED，不能擅换 `glm-5.3` 等模型或用 mock 假装完成；仍交付其他可验证部分，由 C 补实测。不要修改模型桥、账号、生产默认模型、凭证或其他配置来获得测试能力。
5. 必要回归仅覆盖实际差异：S0 授权、S1 召回/纠错与工作档、心核关键行为、工作记忆/归档、运行时回退。若已有失败，只跑同环境相关最小基线复现，不无故重复全部已通过测试、不修改断言掩盖问题。区分基线既有、S2 新增、环境阻断。
