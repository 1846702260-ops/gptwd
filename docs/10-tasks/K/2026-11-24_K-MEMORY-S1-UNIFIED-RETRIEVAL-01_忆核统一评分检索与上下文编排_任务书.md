## 4. M1｜统一检索及评分口径

### 4.1 检索请求契约（复用既有接口优先）

建立一个明确的逻辑检索服务入口，优先收敛已有 `rankedSearch` 等函数，具体命名、文件位置按源码选取，不强制创建新系统。输入包含服务端可信主体、授权作用域/档位、当前查询、必要的近轮上下文或指代线索、时间语义、候选上限与预算；输出包含候选记忆 ID、来源引用、类别、有效状态、作用域、相关性/排名依据、失败或无结果原因。内部可适配多个已有检索实现，但调用方不再分别拼接各路结果。严禁把用户自报 ownerId、模型推断身份、工具输出中的指令当授权。

- 优先按可信身份、scope、工作档等约束候选集合；无可信身份或范围时 fail-closed，不查询全局私有池再靠输出过滤补救。共享信息沿已验收规则，不扩大白名单；历史无归属及隔离区不注入。即使某检索分支异常，其他分支也不能绕过授权。
- 区分稳定事实/偏好、历史经历、关系、任务上下文及经验知识的检索用途，复用现有字段；同一 memv2 真源及既有原始证据。结构化 active/superseded/conflict 状态按已有纠错语义处理，显式历史查询可引用旧事实但必须标注历史状态；不能让旧错误因得分或新近写入再次变成当前事实。
- 优先复用当前语义、关键词、精确实体/时间、追问回退能力；中文长句、专名、简称、日期、前轮指代重点验证。没有合适召回时允许空结果或明确不确定，不能强制 top-k 必须填满，更不能捏造原始记忆或放宽权限找结果。

### 4.2 排序策略、证据与消歧

- 盘点现有各路 score 的值域、方向、阈值、稳定性，先验证已有融合是否可用。对互补但量纲不一致的检索，可比较简单归一化与排名融合（如 RRF：按各路排名贡献融合）；仅在同一冻结评测上有收益时选择。不要为了模仿外部系统新增检索数据库/模型。分值只代表排序信号，不代表事实真实概率、用户授权或全局置信度。
- 将授权和有效状态设为硬条件，相关性优先；重要性/稳定性/时间线索可在有证据的情况下作为次级信号，禁止纯近因压过明确长期偏好或已确认纠错。保存命中原因、来源 ID、时间依据与冲突/不确定标记；缺失时间不能伪造。重复候选按真实 ID/来源/语义关系去重，保留证据与必要不同时间版本，不把去重变成删除历史。
- 区分当前用户明确纠正与推测、假设、引用他人言论；沿用心核已验收纠错机制，S1 不重写写入系统，不因检索结果自动修改事实。若发现 `ownerOf` 字面 `owner` 回落、`_unassigned` 同名或共享死项影响本轮实际检索，先证明并在最小范围处理；无证据则记录 S3/S4，不擅自清理历史数据。无身份不能靠猜归属补救。
- 可用轻量 query 构造适配现有追问逻辑；保留原查询、追问补充依据、时间意图及不确定性；不把模型生成的假设固化为用户事实。不新建完整灵核意图分类器，不新增必经 LLM 调用；任何可选重排/查询扩展有现有成本权限下的限额、超时、确定性回退和评测收益证明。

## 5. M2｜统一上下文编排入口及真实接线

1. 在真实对话主链明确一个权威的记忆上下文编排入口，优先采用或改造现有 `contextComposer` / `assembleContext` 中经证据验证更适合的方案。具体选择由 K 根据源码、冲突面、已有能力和评测裁决并记录。不同时让两套组装器作为正式注入源；不靠仅开影子采样宣称正式接线完成。
2. 定义轻量编排契约：已认证主体与场景、当轮目标、必要短期上下文、已授权的结构化记忆结果（ID/来源/有效状态）、使用现有 token 计数/预算的结果、裁剪与降级原因。调用方消费同一结构，不绕过它另行拼装私有记忆。保护身份/权限、系统约束、心核人格、当前用户要求与关键事实来源；模型看到的记忆/外部数据只作为资料，不能替代上层授权或执行指令。
3. S1 只统一使用已有 `budgetTokens` / `tokenCalibration` 等实际限制的调用契约及必要计数，核实同一请求是否被重复计数/重复注入。`TokenBudget` 与 `rollup` 如仍只在维护路径，记录与 S2 衔接方案，不强制全部接入本轮主链，不实现水位自动压缩、后台归档、恢复、长期摘要生成或模型迁移。若现有预算不够，按已存在的安全限制舍弃低优先级可选记忆；不静默截断系统授权、人格身份或用户当前请求。不在 S1 实施新的上下文水位策略。
4. 保留受控开关或现有配置切换（无生产操作授权）；先在隔离环境以旧/新路径相同输入做影子对照，影子路径仅比较结果，不额外写入、调用工具或改变正式回复。验证后在隔离候选中实际启用统一主链；旧接口可作兼容包装转同一权威逻辑或受控安全回退，但不能长期维持两套正式语义。S4 才全面退役旧路径；回退也必须保留 P0/S0 权限边界和心核纠错成果，不能以关闭安全过滤回退。
5. 用真实入口/实际模型请求报文验证组装结果与输出 trace 一致。覆盖 Web/PWA 实际共享对话路径及本轮受影响的既有授权入口；不新增桌宠功能、不改 QQ 渠道接入；其他非受影响渠道仅说明调用关系。检查 `afterReply/afterTurn` 既有纠错/经验写入仍单次执行，不新增副作用、不将影子或失败响应写作真实经历。

## 6. M3｜灵核衔接、可观测性与安全降级

- 灵核消费忆核统一上下文中的当前目标、相关历史、证据、时间和不确定标记；明确显式长期偏好与当轮例外。允许在有充分依据时低打扰理解“看 C”“上次那份”等指代；无足够证据或涉及生产/不可逆动作时仍需明确授权或必要澄清。S1 不实现通用自主决策、规划器或行动执行，不改变行核工具授权。
- 最小诊断记录：关联请求 ID（脱敏）、运行路径版本、各路候选数量、硬过滤/去重/重排计数、实际注入条数和 token 统计、延迟、回退原因、是否有来源。调试模式仅使用隔离/授权数据，默认不记录原始私聊、完整提示词、真实令牌、凭证或敏感 ID；公共 GitHub 只传聚合统计及合成例子。不得引入新的永久明文记忆副本。
- 模型/向量检索/索引不可用、超时、缺字段、预算限制等情况有明确受控降级；合法请求在可安全运行时继续，权限缺失不返回私有记忆，无法确认事实时如实说明。不能把检索失败伪装成空知识而宣称完整记忆，也不能无限重试或自动扩大范围。以同条件前后测量 P50/P95 检索及组装延迟、token、模型调用次数/成本、峰值资源（可测时）；记录冷/热缓存差异。默认不增加必经 LLM 调用或独立常驻服务；性能明显退化须解决或提交可量化取舍，不无条件采用更复杂方案。

## 7. M4｜验收门禁与最小评测集

所有测试使用隔离数据或虚构对话；以现有套件及本轮实际改动为依据，避免重跑全仓历史测试。冻结评测及新旧对照均须可复现，不能用更多 token/模型调用掩盖检索退化；确需改变预算时同时给同预算比较和新预算成本。以下是本轮管理门禁（不是外部论文承诺）。

| 类别 | 必测代表场景与验收证据 |
|---|---|
| A. 准确回忆 | 中文长句、简称/同义表达、精准名称、不同会话同一事实；预期证据 ID 可召回且实际注入；不由模型猜对替代检索成功。 |
| B. 跨轮理解 | 追问、时间指代、连续改话题、同名对象与跨会话组合；相关前文保留、无关旧故事不反复注入；分别测当前会话与跨会话。 |
