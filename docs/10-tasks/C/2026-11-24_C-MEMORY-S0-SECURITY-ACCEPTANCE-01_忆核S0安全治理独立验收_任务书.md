### M1｜三项安全修复的独立验收

所有测试使用隔离环境、合成身份与虚构记忆数据，不读取、迁移或删除真实主人记忆。合成身份可用于组件级验证，须标为测试夹具，不冒充真实登录身份。

#### S0-1：经验记忆（lessons）隔离

- 验证写入关联可信 ownerId，检索按真实授权主体过滤；不同主体的经验事实不能互相进入提示词或响应。
- 验证缺字段、身份不确定、历史无归属或不一致记录时失败关闭，不能回退到全局经验池或默认主人；旧记录不被静默删除。
- 正向控制：合法主体仍可写入和检索自身记忆，隔离逻辑不是通过关闭所有记忆达到假通过。区分经验/事实记忆及现有工作/私聊场景边界。

#### S0-2：归档分片隔离

- 验证按 uid 分目录的真实读写、身份变更与不同用户的归档范围，异常路径与文件名不越过预期目录。
- `_unassigned` 与历史无明确归属数据不得被自动注入，不以批量猜测 ownerId 归并历史数据；检查原始记录保留和失败路径的日志。
- 核实归档恢复/召回时不会绕开归属过滤，隔离重启后同样生效。通过哈希或内容比对证明夹具之间没有串读或破坏。

#### S0-3：DSH/旧入口安全降级

- 检查 `noTools` 的结构性工具移除实际有效，不仅是 prompt 声明；未授权入口不能调用高权工具、写主人记忆或取得主人身份。
- 验证已配置 token 且凭证缺失/错误时拒绝（K 报告 403），未配置时按 guest 降级；同时证明合法授权路径按既有策略可用，guest 不读取私人主人记忆。
- 实际 HTTP 测试及组件调用分别记录，确认同一路由授权边界、检索过滤和工具注册状态。不得通过开放旧入口或绕过门禁构造所谓验收环境。

### M2｜S0-B 可信身份源：明确阻断，不扩大架构

K 报告设置 ownerId 后设备均折叠为同一主人，无法用正常 HTTP 登录入口形成普通成员 A/B。C 必须独立核对这一限制究竟来自配置、测试环境、合法身份提供方式还是产品架构。

1. 梳理真实身份从认证入口、会话/设备绑定、可信主体映射、记忆读取/写入直至工具授权的链路。分清主人、普通成员、服务身份、guest、未认证身份。仅收集必要源码与隔离行为证据，不改生产身份配置。
2. 若现有正式授权接口已支持可验证的非主人身份，在隔离环境使用合成账号通过**正常认证入口**完成 A/B 互不串读、非主人不能改主人记忆、跨会话/重启持久化、无授权工具拒绝。写明账户取得方式、授权主体及真实响应。不得临时关闭安全功能、注入虚假的主人身份或暴露真实凭证。
3. 若现有身份源确实不能支持该场景，保留 BLOCKED，记录已核对路径、可验证的组件边界、无法验证的入口边界和最小前置依赖。不得把所有设备等同主人视为多用户隔离测试通过；也不得把“无法测”直接认定为三项修复失效。
4. 结合 P0 最终候选的 U1 安全默认值、R3 身份类型/撤销机制和相关认证改动，判断它们是否**可能**提供所需可信身份基础；必须用实际候选差异或隔离证据确认，不靠版本号推断。若需要组合后才能验证，明确后置门禁和具体依赖。
5. 输出风险归因：若正常使用路径存在跨主体读写或越权实证，为 A 类；若仅验证能力缺失，说明验证门禁为何阻断、现有实际暴露面、隔离/规避条件及仍待裁决事项。不擅自将已有阻断降级，也不因此自动扩大 P0。
6. 允许范围内最小测试或接线缺陷修复；若需新身份提供者、认证模式改造、权限模型重构或改变主人唯一授权语义，停止该项，提出最小方案与影响供 ChatGPT 裁决。本轮不新建正式身份系统。
